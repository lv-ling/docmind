# P13 业务文档列表

## 页面定义

- 路由：`/business-documents`，对应原型 `#bizdocs`。
- 目标：检索从已发布 fillable 模板创建的唯一当前业务文档并进入对应动作。

## 布局

- 页头：标题、单一当前内容说明、“新建业务文档”。
- 筛选栏：关键词、编辑模式、流程状态、当前处理人、发起人、模板、时间范围、回收站。
- 表格与分页；行主操作由当前状态与当前用户能力决定。

## 列表字段

名称、来源模板/版本、业务元数据摘要、模式 `internal/external`、流程状态、当前责任人、审批进度、更新时间、操作。

页面不显示“业务版本号”。内部 `content_revision` 只用于写冲突控制，不作为列表字段。

## 行操作

- draft：继续配置、删除。
- editing_internal：当前处理人“去填写”；其他人查看；发起人可按规则取消。
- editing_external：复制/管理外链、查看；内部用户没有正文编辑入口。
- awaiting_approval：当前审批人“去审批”；其他人查看。
- completed：查看、下载最终 DOCX/PDF、进入回收站。
- cancelled/recycled：查看审计或按权限恢复/清理。

## 空态与权限

- 无已发布 fillable 模板时说明先发布模板，并提供模板中心入口。
- 无创建能力时隐藏新建按钮。
- “我的文档/我发起的/我处理的/全部可见”作为快捷筛选，不改变服务端对象权限。

## 实现拆分

- 新建 `views/business-document/list`，不沿用旧 `instance version` 用户术语。
- `DmDataTable` + URL query；状态/动作使用集中 capability mapper。
- 行内复制外链只能复制公开入口 token，不包含内部对象 ID 或存储地址。

## 验收

- 内外部模式不可能同时显示编辑入口。
- 审批人没有填写/正文编辑入口。
- 完成文档只读，创建新业务必须回模板向导。
- 删除/回收站动作符合状态规则并二次确认。

## 子任务

- P13-T1：实现业务文档列表/筛选/动作契约。
- P13-T2：实现状态能力映射与表格。
- P13-T3：补角色、模式、删除和回收站测试。
