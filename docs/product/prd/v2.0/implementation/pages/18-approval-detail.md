# P18 审批详情

## 页面定义

- 路由：`/tasks/:taskId/approval`，对应原型 `#approval-view`。
- 访问：当前审批处理人；其他有查看权限者只读且无处理按钮。
- 目标：基于固定提交快照进行顺序审批，不允许修改正文。

## 布局

- 顶部：待办状态、文档名、审批级次、提交人/时间、快照摘要、批准/驳回/转交/传阅。
- 主区：只读 PDF/文档快照。
- 右栏：字段摘要、前序审批意见、当前审批意见、审批链。
- 下方：相关时间线和批注。

## 字段

审批意见可选（工作区可配置必填）；驳回原因必填；转交对象、说明、截止时间；传阅对象、说明、有效期。

## 动作

- 批准：生成批准快照；有下一人则创建下一审批待办，最后一人批准后完成并生成最终文件。
- 驳回：填写原因；内部模式退当前编辑人，外部模式选择重新开放原链接或生成新链接；审批链关闭。
- 转交审批：选择有审批能力成员，仅替换当前节点处理人，不改变后续顺序。
- 传阅：创建只读快照旁路，不改变当前审批待办。

再次提交后审批链从第一位重新开始，所有审批人审核同一提交快照。

## 安全与并发

- 页面无任何字段输入/正文编辑控件。
- 所有处理请求带 task ID、snapshot ID、幂等键和预期 task revision。
- 任务已处理/转交时 409，页面刷新并显示实际处理人和时间。

## 验收

- 审批人无法通过 API 修改文档内容。
- B 批准后 C 才收到待办；任一驳回后再次提交从 B 开始。
- 重复批准不会产生重复快照、待办或完成事件。
- 外部驳回必须明确选择链接恢复策略。

## 子任务

- P18-T1：实现顺序审批状态机与动作契约。
- P18-T2：实现只读快照、审批链和四类动作。
- P18-T3：补多级、驳回重启、转交、幂等 E2E。
