# P17 我的待办

## 页面定义

- 路由：`/tasks`，对应原型 `#tasks`。
- 目标：集中处理抽取复核、内部填写、审批、外部提交复核、传阅和失败重试事项。

## 布局

- 顶部统计：待处理、即将到期、逾期、传阅未读。
- Tab：全部、填写、审批、抽取复核、外部提交、传阅、失败事项。
- 筛选：关键词、状态、发起人、截止时间、优先级；支持分页和排序。
- 表格/卡片响应式展示，主操作始终明确。

## 字段

文档名称、待办类型、当前状态、发起人、处理人、创建时间、更新时间、截止时间、优先级、置信度（抽取）、处理轮次、主操作。

## 操作

- 填写：去填写、转交（在详情完成）。
- 审批：去审批。
- 抽取：去复核。
- 传阅：查看快照并确认已阅；不能编辑、转交或再传阅。
- 失败：查看失败阶段和可重试动作。

待办处理、转交或取消后立即从活动列表移除或进入已处理状态；重复点击不能重复执行业务动作。

## 实现拆分

- 统一待办 DTO，使用 type discriminator；不要让前端拼接多个领域列表。
- `TaskPrimaryAction` 按类型和 allowed_actions 渲染。
- SSE 只刷新变更任务；列表分页状态保留在 URL。

## 验收

- 用户通过猜测 task ID 不能查看他人待办。
- 待办状态变化时已打开页面立即只读/失效。
- 传阅确认不改变主流程处理人和状态。
