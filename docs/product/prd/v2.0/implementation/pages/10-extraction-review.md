# P10 抽取人工复核

## 页面定义

- 路由：`/extractions/:id/review`，对应原型 `#extraction-review`。
- 目标：逐字段对照证据处理 AI 结果，最终批准不可变结构化数据或驳回整次任务。

## 布局

- 顶栏：输入名、方案版本、整体置信度、处理进度、驳回、批准/提交批准申请。
- 左栏（约 42%）：`DmPdfViewer` 与证据高亮。
- 中栏（约 25%）：可折叠字段树，显示状态、来源和置信度。
- 右栏（约 33%）：字段值、候选、证据、敏感等级、人工操作记录。
- 分栏可拖动/折叠，偏好按用户和工作区保存。

## 字段复核内容

当前值、类型、来源 `extracted/default/manual`、置信度、候选值、证据页码/引文/框、必填/nullable、敏感展示、处理状态、最后修改人/时间。

每个字段支持：接受、选择候选、手工修改并填原因、标记原文未找到、标记需要进一步确认。数组/对象使用树状编辑，不用纯 JSON textarea 作为唯一入口。

## 交互规则

- 选择字段自动定位并高亮证据；多证据可前后切换。
- 敏感字段仅在有明文 capability 时取明文；其他角色只收到掩码展示。
- 手改后立即做类型/Ajv 校验，保存时服务端再次校验 Schema、证据和 PII。
- 所有必填字段处理完成且无阻断错误才可批准。
- 无证据字段必须由人工明确选择处理方式，不能自动接受。
- 双人模式下，最后修改字段者只能提交批准申请，另一批准人最终批准。

## 并发与状态

- 获取复核租约或使用字段级乐观 revision；他人已处理时页面转只读并刷新。
- approved/rejected 页面只读；批准结果可导出 JSON。
- 批准、驳回和字段修改全部带幂等键并记录审计。

## 实现拆分

- 延续 `useExtractionReview`，拆分 `EvidencePdfPane`、`ReviewFieldTree`、`FieldReviewInspector`。
- 证据定位复用 `DocumentEvidenceAnchor`。
- 纯 model 负责字段树、display value 和处理完成度。

## 验收

- 每个批准字段都有证据或明确人工处理记录。
- 无敏感权限时网络响应、DOM、日志和导出都没有明文。
- Schema 错误准确定位到字段，不能批准。
- 双人模式和默认单人模式均按规则完成。

## 子任务

- P10-T1：补复核动作、原因、双人批准和字段 revision 契约。
- P10-T2：实现三栏、证据定位与嵌套字段编辑。
- P10-T3：补敏感权限、并发、幂等和批准 E2E。
