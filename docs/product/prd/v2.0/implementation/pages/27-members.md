# P27 成员与权限

## 页面定义

- 路由：`/settings/members`，对应原型 `#members`。
- 访问：Owner/Admin；Owner 角色变更需更严格规则。
- 目标：管理工作区成员、角色、状态、敏感明文能力和双人复核设置。

## 布局

- Tab：成员、角色能力、审批/复核设置。
- 成员表：姓名、邮箱、角色、状态、加入时间、最近活动、操作。
- 添加/修改 Drawer：成员信息、角色、对象/敏感能力范围（如产品支持）。
- 设置卡：抽取双人批准开关、编辑人/审批人兼任规则。

## 角色

Owner、Admin、Editor、Reviewer、Viewer。外部填写人不是工作区成员，不能在此创建。

## 操作规则

- 邀请/添加、修改角色、停用、重新启用、移除。
- 不能移除最后一个 Owner；用户不能把自己降级导致工作区无 Owner。
- 停用当前待办处理人前列出受影响待办并要求先转交或由管理员执行受审计迁移。
- 角色变更后服务端每次请求重新查成员关系，旧 JWT 不保留旧角色权限。

## 验收

- 猜测成员 ID 不能跨工作区操作。
- 停用成员不会产生无人处理的活动待办。
- 敏感明文能力变化立即影响后续响应和已打开页面。
- 角色变更审计包含操作者、前后角色和请求 ID，不含敏感数据。

## 子任务

- P27-T2：实现成员表、编辑 Drawer 和设置。
- P27-T3：补最后 Owner、停用迁移和权限即时失效 E2E。
