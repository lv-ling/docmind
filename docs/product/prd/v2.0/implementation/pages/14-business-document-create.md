# P14 新建业务文档向导

## 页面定义

- 路由：`/business-documents/new`，对应原型 `#bizdoc-wizard`。
- 目标：选择固定模板版本、预填数据并创建内部或外部唯一编辑模式及顺序审批链。

## 布局与步骤

1. 选择模板：仅 published + fillable + 当前有权限版本。
2. 基本信息：名称、业务元数据、可选字段预填。
3. 编辑模式：内部编辑或外部填写，二者互斥。
4. 审批与规则：人员、顺序、外链配置。
5. 确认：展示所有固定输入、权限和后果后创建。

## 字段

| 分组 | 字段 |
| --- | --- |
| 模板 | template_id/version_id、模板类型、字段数、发布者、发布时间 |
| 基本 | 文档名称、业务编号/分类/标签（按工作区配置）、备注 |
| 预填 | 模板授权字段的 typed value；敏感字段按权限展示 |
| 内部模式 | 唯一初始编辑人、截止时间、至少一位顺序审批人 |
| 外部模式 | 至少一位顺序审批人、有效期、访问码开关、最大尝试次数、是否允许暂存、允许查看/填写字段范围 |

审批人使用可排序列表；每一项显示姓名、角色、状态和审批级次。不能选择停用用户；内部编辑人是否可兼任审批人按工作区规则校验并明确提示。

## 创建规则

- 创建时固定引用模板版本，模板后续发布不影响该文档。
- 内部模式创建一个编辑待办，不创建外链。
- 外部模式创建唯一有效外链，不创建内部编辑待办。
- 预填值服务端按 bindings + JSON Schema 校验。
- 创建请求带幂等键；成功后跳详情并显示待办或一次性可复制外链。

## 实现拆分

- `TemplateVersionPicker`、`BusinessMetadataForm`、`BoundFieldForm`、`EditModeSelector`、`OrderedApproverList`、`ExternalLinkRules`、`CreationSummary`。
- 向导状态放页面 composable，不进全局 Pinia；刷新可选择用无敏感 server draft 恢复。
- 成员选择用远程 `DmCombobox`，不一次下发全部成员。

## 验收

- reference、未发布、blocked 模板不能被选择。
- 两种模式 UI、请求和服务端状态严格互斥。
- 内部模式缺编辑人/审批人、外部模式缺审批人均不能提交。
- 重复提交只创建一个业务文档和一套活动对象。

## 子任务

- P14-T1：定义创建联合请求和审批链契约。
- P14-T2：实现五步向导与字段预填。
- P14-T3：实现幂等创建、成员校验和模式互斥 E2E。
