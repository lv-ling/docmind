# P24 智能审阅列表

## 页面定义

- 路由：`/reviews`，对应原型 `#review`。
- 目标：查看智能审阅任务和处理进度，并从上传/系统文档发起新审阅。

## 布局

- 页头：标题、能力说明、“发起智能审阅”。
- 筛选：关键词、输入类型、状态、严重问题、是否可编辑、创建人、时间范围。
- 表格：文档、固定输入、状态、问题数分级、已处理数、更新时间、操作。
- 创建 Dialog 复用 `DocumentPicker`；上传先变为不可变原件。

## 字段与状态

- 输入类型：上传原件、系统原件版本、模板版本、业务文档审阅快照。
- 状态：queued/analyzing/review_required/completed/failed/cancelled/outdated。
- “质量分”不是 PRD 必需，若保留必须有透明公式；默认以问题分级和处理进度为主。

## 操作

- 运行中：查看进度/取消。
- review_required：进入审阅。
- completed：查看结果/导出。
- failed：查看安全诊断并按固定输入重试。
- outdated：查看旧快照结果或针对最新内容重新运行。

## 可编辑性

列表只显示“只读/可应用建议”能力标签。只有 editing_internal 当前处理人可应用；上传、原件、模板、外部、审批、完成业务文档均只读。

## 验收

- 上传文件不会从审阅入口创建业务文档。
- 任务固定输入在文档后续变化后仍可查看并标 outdated。
- 状态/问题数和详情一致，权限失效不泄露文档名。

## 子任务

- P24-T1：定义审阅列表/创建/状态契约。
- P24-T2：实现列表、创建 Dialog 和实时状态。
- P24-T3：补输入类型、可编辑能力和过期测试。
