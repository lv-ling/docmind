# 这是我的原始需求

## 结论摘要

DocMind 当前不是一个通用“文档管理系统”，而是围绕不可变原件形成两条主要产品链路：

```text
不可变原件
├── 结构化数据链路：Schema → 安全抽取 → 人工复核 → 批准结果
└── 文档模板链路：文档解析 → 模板转换 → 预览/poc编辑调整（尽可能还原doc文档编辑） → 发布（发布后再pdf预览是经过poc编辑调整的文档）/恢复
└── 文档流转链路：模板不可变 → 类似复制一份新的文档 → 发送待办给某个用户 → 此用户可以进行编辑 选择驳回或者通过 或者 发送待办给下一位用户 或者 传阅给下一位用户（传阅给的下一位用户不可编辑只能查看，并且此用户不可传阅给其他用户）
└── 文档比对：用户可以将任意两份文档进行比对 - 比如上传两份文档 或者 上传一份文档从系统中选择一份已上传文档或者模板或者已经发起过待办的文档 或者 两份文档都从系统中选择 比对时可以如果有一份是系统中的文件可以根据用户的进入操作判断时候可以编辑，比如用户点击的仅比对进入则只能比对两份文档的不同，如果点的比对并调整则可以比对不同，并且能够调整那份系统中的文件并进行保存（模板文件不可编辑）
└── 智能纠错（这个功能是不是功能名可以不叫这个，有其他的选择？）：选择用户编辑过的文档（不是模板文档），这有个列表，点击列表中的某一个进入文档详情，左边是文档详情可以编辑，右边是一个ai对话框可以和ai对话进行一些简单的交互，进入详情默认在对话中发送提示词对此文档进行智能纠错（ai对话框组件可以参考 ant desgin x 的组件），同时也可以在这个对话框中进行一些比如 分析文档大致的内容 统计文档中的数据等等，在ai对话框中返回消息和用户交互
```

## 1. 身份认证与会话

模块名称：身份认证

功能描述：

- 邮箱、密码登录。
- Bearer Token 身份认证。
- 查询当前用户。
- Token 保存在当前浏览器标签页的 `sessionStorage`。
- 会话失效后跳转登录页，并尝试恢复原工作区路径。
- 退出登录仅清除浏览器会话。

## 2. 工作台

用户可以在此工作台看到需要复核的文档任务，左侧卡片展示，卡片内容文档名称，置信度，上传时间（几分钟或几小时或一天前超过一天写明日期），可以点击卡片上的复核按钮去复核
右侧有个统计区块，可以看到这个一共处理了几个文档，成功抽取多少份，准确率等
可以快速到复核队列查看所有需要复核的文档列表，也可以快速上传原始文文档
可以根据后续功能再工作台增加一些功能，后续你可以补充

## 3. 文档管理（或者其他命名？）

用户可以在此页面上传文档，文档类型可以为 .doc .docx .pdf , 这是用户的原始文档，此文档为永远不会变的，用户可以使用这份文档去选择想要抽取的字段（此功能再下面schema配置功能），用户可以将这份文档转换为模板，这份模板会有版本管理进行迭代（此功能再下面模板管理实现）
用户上传文档后状态为 - 状态值 register 状态描述 已登记
用户上传文档后抽取字段转换为json中 - 状态值为 extract 状态描述 抽取中
用户上传文档后抽取字段用户上传文档后抽取字段转换为json抽取成功后 - 状态值为 extractionSuccess 抽取成功
用户上传文档后抽取字段用户上传文档后抽取字段转换为json抽取失败后 - 状态值为 extractionFailed 抽取失败
用户上传文档后抽取字段用户上传文档后抽取字段转换为json抽取失败后 - 状态值为 extractionRejected 抽取拒绝
用户上传文档后转换为模板中 - 状态值为 conversion 状态描述为 转换中
用户上传文档后转换为模板中 - 状态值为 conversionSuccess 状态描述为 转换成功
用户上传文档后转换为模板中 - 状态值为 conversionFailed 状态描述为 转换失败

用户只能转换一次模板除非转换失败可以在次转换模板，用户可以多次提取json（提取json作为一个异步任务，后台执行，用户可以查看提取任务列表，点击查看任务详情，以及字段出处，转换后的结果，是否同意转换结果，这功能再下面会详细说明）

功能描述：

- 上传 DOC、DOCX、PDF。
- 最大文件大小 10MB。
- 浏览器计算 SHA-256。
- 通过预签名地址直接上传对象存储。
- 服务端验证文件签名、MIME、大小、摘要和对象 ETag。
- 每个逻辑文档可以拥有多个不可变版本。
- 生成安全 PDF 预览。
- 查看、下载不可变原件。
- 从特定原件版本发起抽取或模板转换。
- 后台清理过期上传会话和 staging 文件。
- 文档列表需要分页查看，需要能筛选 搜索文件名

## 4. 文档抽取（或者其他命名？）

- 选择一个不可变原件版本或者已经编辑好的文档或者直接上传一个新的文档。
- 选择已发布 Schema 版本。
- 可选敏感规则模板版本。
- 创建异步抽取任务。
- 复核原件摘要。
- 解析 DOC、DOCX、PDF。
- 执行敏感检测与稳定令牌化。
- 执行 Schema 约束抽取。
- 校验输出预算、结构、证据、令牌和 PII。
- 受控恢复敏感值并加密保存结果。
- 完成后进入人工复核。

## 5. schema配置（或者其他命名？）

- 创建结构化抽取字段。
- 支持 string、number、integer、boolean、date、datetime、object、array。
- 配置必填、nullable、字面量默认值、敏感等级和抽取提示。
- 服务端生成严格 JSON Schema。
- Schema 按不可变版本管理。
- 后端支持创建 Schema 新版本。
- 后端支持把已发布 Schema 版本保存为可复用模板。
- 明确定义 AI 应从文档中返回什么数据。
- 固化某次抽取使用的字段版本。
- 在相似业务中复用字段结构。

## 6. 敏感信息规则（或者其他命名？）

- 支持九国规则：CN、US、JP、KR、DE、FR、GB、AU、NL。
- 支持 Presidio、RE2 正则、词典和受控 Validator。
- 支持电话、邮箱、身份证件、护照、银行账户、姓名、位置等数据类型。
- 抽取前将敏感明文替换为稳定令牌。
- 敏感令牌映射由 Java API 加密存储。
- 模型只能看到令牌化文档。
- 模型输出经过令牌、证据、Schema 和 PII 二次校验。
- 字段结果按角色返回明文或掩码。
- 避免业务敏感数据直接发送给外部模型。
- 按工作区配置适用的敏感识别规则。
- 让复核人员在权限范围内查看必要信息。

## 7. 人工复核（或者其他命名？）

- 实时显示抽取状态。
- 查看被抽取的文档 PDF查看。
- 查看字段值、置信度、来源、候选值和证据。
- 支持接受、修改、拒绝字段。
- 所有字段完成复核后批准结果。
- 敏感字段按角色掩码。
- 修改后再次执行 Schema 校验。
- 复核和批准请求具备幂等保护和审计记录。
- 验证 AI 结果是否可靠。
- 根据原文证据修正错误。
- 形成可以正式使用的批准数据。

## 8. 文档模板（或者其他命名？）

- 从原件版本创建模板转换任务。
- 生成 PDF 对照预览。
- 模板版本不可变。
- 支持对模板进行编辑调整使用 poc编辑高度还原doc文档。
- poc文档编辑保存后生成新的模板版本，在预览新版本的文档就是调整后的模板文档
- 保存产生新版本。
- 服务端计算模板版本结构 Diff。
- 有阻断告警时禁止发布。
- 支持发布和“生成新版本式恢复”。
- 将不可编辑原件转换为可复用模板。
- 人工确认转换质量。
- 保留所有修改和发布历史。
- 在不改写历史版本的情况下恢复旧内容。

## 原生 DOCX 编辑 POC （此功能是作为一个功能，可能会有多页面引用这个组件使用）

- 创建短期 ONLYOFFICE 编辑会话。
- 使用受控下载 URL 和 JWT 回调。
- 对保存结果进行文件大小、ZIP、OOXML、路径穿越和 VBA 安全校验。
- 保存到独立 POC 对象路径。
- 查询回调和保存状态。

这是现在还未完成的一些内容：

- G0 还原度门禁未通过。
- 保存文件不会创建正式模板版本。
- 没有字段 Content Control 绑定。
- 没有模板版本 PDF 快照状态机。
- 没有正式数据库编辑会话。
- 当前仅接受 DOCX。
- 授权、代表样本、故障矩阵尚未完成。

## 文档Diff （或者其他命名？）

- 用户上传两份新文档进行比对
- 用户选择系统中的文档进比对
- 用户上传一份文档选择一份系统中的文档进行比对
- 选择系统中的文件可以是模板，模板不可编辑改动
- 选择系统中的文件可以是原件，原件不可编辑改动
- 选择系统中的填写过的文档也就是发送待办填写了数据的文档，允许编辑保存

## 文件生成（或者其他命名？）

- 可以选择已经生成的文档模板进行文件生成
- 模板文件是不改动的，生成的文件可以进行编辑保存，将此文件发送待办给其他用户

## 智能纠错（或者其他命名？）

- 用户可以上传一份文档纠错
- 用户可以选择系统中的模板纠错，不可编辑
- 用户可以选择系统中根据模板生成的文档纠错，可以编辑保存
- 用户在列表上选择文件后，点击文件进入详情
- 进入详情后，左边默认根据是否可编辑来进行展示，如果不可编辑则pdf展示，如果可编辑则poc编辑器展示
- 进入详情后，右边是ai交互框，进入详情自动发送提示此智能纠错，让ai返回信息哪些部分是有错误（文字错误 语法错误等等）
- 用户可以在ai对话框中对话，可以问其他问题，比如整理文档信息 文档归纳成图标 等等一些其他问题ai都能处理

## 文档填写（或者其他命名？）

- 用户可以经由文件模板发起文档填写
- 可以通过待办方式发送给系统用户，让用户去填写文档，根据待办id请求对应文档和当前登录人是否是文档填写人，如果登录人等于填写人则可以填写文档保存或者提交
- 可以发起文档填写，但是并不是发给系统用户，只是生成一个链接，复制链接发送给其他人就可以在网页上打开页面填写数据保存或提交数据
- 文档填写详情不用poc那种原始werd文档编辑的样式与方式，而是后端根据文档中的某些占位符，比如在模板中编辑保存 名称：**${name}** 类似这样的占位符，则文档填写可以根据这样的占位符判断需要在哪里填写，用户直接在**\_** 上进行填写还是点击 \_\_\_\_ 在这个下划线上给填写提示点击弹出弹窗里面有输入框进行填写，看能不能实现第一种，不行就实现第二种
