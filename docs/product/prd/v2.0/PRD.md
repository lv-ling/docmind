## 1. 文档目的

本文档定义 DocMind 的完整产品范围、核心对象、权限、状态、页面和端到端业务流程，作为产品评审、交互设计、技术设计、开发拆分和最终验收的统一依据。

本文档中的“必须”表示发布前必须具备；“应该”表示默认纳入产品设计，但可在单独评审后调整交付顺序。分阶段交付不改变本文档定义的最终全功能范围。

## 2. 产品概述

### 2.1 产品定位

DocMind 是一套围绕不可变文档原件构建的智能文档处理与协作平台。它不是通用文件网盘，也不是浏览器中的完整桌面 Word 替代品，而是将企业文档转化为可抽取、可复用、可填写、可流转、可对比、可审阅和可审计的业务资产。

产品形成四条核心闭环：

```text
不可变原件
├── 结构化数据闭环：抽取方案 -> 安全抽取 -> 人工复核 -> 批准数据
├── 模板生产闭环：模板转换 -> 原生编辑 -> 质量检查 -> 发布/恢复
├── 业务协作闭环：文档生成 -> 填写/编辑 -> 内部流转或外部填写 -> 完成归档
└── 质量改进闭环：文档对比或智能审阅 -> 人工确认调整 -> 保存业务文档
```

### 2.2 用户问题

- 原始 Word/PDF 中的数据需要人工阅读和重复录入。
- 敏感信息不能直接发送给外部模型。
- Word 模板转换后版式、字段和历史修改难以追溯。
- 文档填写依赖线下传文件，无法确认当前处理人和最终内容。
- 两份文档的文字、结构、表格、格式和字段变化难以准确定位。
- AI 纠错和问答缺少证据、权限控制以及修改确认机制。

### 2.3 产品目标

- 保存并验证不可变的 DOC、DOCX、PDF 原件。
- 将用户定义的抽取字段固化为可版本化、可复用的抽取方案。
- 在敏感信息不泄露的前提下完成结构化抽取和人工批准。
- 将原件转换为可复用模板，保留编辑文件、字段绑定、PDF 快照和版本历史。
- 根据模板生成可填写的业务文档，支持系统用户待办和外部链接填写。
- 支持任意两份允许访问的文档进行对比，包括“两份上传、一份上传加一份系统文档、两份系统文档”。
- 对当前内部编辑人提供“对比并调整”，保存时更新同一份业务文档。
- 提供带文档证据的智能审阅和 AI 对话，任何修改都由用户确认。
- 对上传、抽取、复核、编辑、发布、流转、对比和 AI 操作进行审计。

### 2.4 非目标

- 不提供未经人工确认的自动法律结论。
- 不包含电子签章、实名认证或具有法律效力的签署流程。
- 不承诺任意复杂 DOC/PDF 的 100% 像素级可编辑还原。
- 不允许直接覆盖原件或已发布模板版本；业务文档始终只有一份当前内容。
- 首期不提供多人同时无锁编辑和自动合并，采用单人编辑租约。
- 不允许 AI 自动修改文档或自动批准抽取结果。

### 2.5 成功指标

| 指标 | 目标与口径 |
| --- | --- |
| 敏感明文外发率 | 0；模型请求、响应和日志均纳入检查 |
| 抽取字段证据覆盖率 | 100%；无证据字段必须进入人工处理 |
| 常见字段抽取准确率 | 已完成人工批准的黄金集字段准确率不低于 90% |
| 抽取任务成功率 | 排除用户取消和非法文件后，成功进入复核的任务占比 |
| 文档处理性能 | 10MB 以内常见文件，解析与抽取 P95 不超过 2 分钟 |
| 编辑并发安全 | 不发生无提示覆盖；冲突必须显式提示 |
| 资产可追溯率 | 原件/模板版本以及业务文档提交、审批和对比快照均可追溯到操作者和来源 |
| 对比可重放率 | 已完成的权威对比均可由双方原件/模板版本或业务文档快照和算法版本重放 |

## 3. 用户、角色与权限

### 3.1 用户类型

| 用户类型 | 主要职责 |
| --- | --- |
| 工作区所有者 | 管理工作区、成员、角色、数据安全和系统配置 |
| 管理员 | 管理成员权限、敏感规则、模型配置、审计和业务数据 |
| 编辑者 | 上传原件、创建抽取方案、设计模板、生成和编辑业务文档 |
| 复核者 | 复核抽取结果、处理分配给自己的业务待办和外部提交 |
| 查看者 | 查看被授权的文档、结果、对比和传阅内容 |
| 外部填写人 | 仅通过有效链接访问指定业务文档的指定填写字段 |

### 3.2 权限判定原则

一次操作是否允许，必须同时满足：

1. 当前用户属于目标工作区；外部填写人除外。
2. 工作区角色拥有对应能力。
3. 用户拥有目标对象的查看或编辑权限。
4. 用户是当前待办处理人，或具有管理/复核权限。
5. 对象当前状态允许该操作。
6. 敏感字段还需单独的明文查看权限。

仅知道文档 ID、版本 ID、待办 ID 或外部链接地址，不代表拥有访问权限。服务端必须在每次请求时重新校验权限，不能只依赖页面入口是否可见。

### 3.3 关键权限规则

- 原件对所有角色均不可编辑。
- 已保存的历史模板版本不可编辑；模板设计者只能基于其创建新草稿。
- 业务文档不向用户提供版本号；普通保存、对比调整和 AI 建议应用都更新同一份业务文档。
- 只有当前内部编辑待办的处理人可以修改流转中的业务文档；审批人只能审批，不能修改正文。
- 被传阅人只能查看和确认已阅，不能编辑、转交或继续传阅。
- 外部填写人只能查看链接授权的字段和必要文档上下文。
- 无敏感明文权限的用户只能看到掩码值，但仍可看到字段是否存在、处理状态和非敏感证据。
- 抽取结果默认允许具有复核权限的同一用户完成复核和批准；工作区可以启用双人模式，要求最终批准人与最后修改字段的复核人不同。

## 4. 核心概念与对象边界

| 对象 | 定义 | 核心规则 |
| --- | --- | --- |
| 工作区 | 用户、文档和配置的租户边界 | 所有业务对象必须属于一个工作区 |
| 逻辑文档 | 一份原始文档的业务容器 | 可以包含多个不可变原件版本 |
| 原件版本 | 用户上传并通过验证的 DOC、DOCX、PDF | 永不覆盖；支持查看、下载和派生任务 |
| 抽取方案 | 用户定义的结构化字段集合 | 草稿可编辑，发布版本不可变 |
| 敏感规则方案 | 按国家、类型和自定义规则组合的数据安全策略 | 发布版本不可变，任务固定引用版本 |
| 抽取任务 | 针对原件版本或业务文档抽取快照执行的一次结构化抽取 | 固定输入、方案、规则、模型和提示词版本 |
| 批准结果 | 经人工复核并批准的结构化数据 | 不可变；修改需产生新的复核结果版本 |
| 模板 | 可复用文档的逻辑容器 | 包含多个不可变模板版本 |
| 模板草稿 | 基于原件或历史模板版本创建的编辑工作副本 | 持有编辑租约时可修改；自动保存不形成正式版本 |
| 模板版本 | DOCX/PDF、字段绑定、PDF 快照和派生模型的组合 | 一经创建内容不可变；发布只改变可用状态和当前版本指针 |
| 业务文档 | 从已发布且可填写的模板创建、承载业务数据并参与流转的唯一当前文档 | 固定引用创建时的模板版本；不提供用户可见版本 |
| 业务文档审计快照 | 系统在提交、驳回、批准、抽取、对比和智能审阅等关键时点固化的内部内容快照 | 不显示业务版本号，不可编辑、恢复或作为日常文档操作入口 |
| 流程实例 | 一份业务文档从发起到结束的处理过程 | 记录当前责任人、历史处理人和终态 |
| 用户待办 | 流程分配给系统用户的编辑或审批任务 | 同一主流程同一时刻只有一个活动任务；审批任务只读 |
| 外部填写链接 | 授权非系统用户填写指定业务文档的短期凭证 | 可过期、撤销、限制次数和再次开放 |
| 文档对比任务 | 两个原件/模板版本或业务文档对比快照之间的权威差异结果 | 固定双方输入、算法版本和发起人 |
| 智能审阅任务 | 对原件/模板版本或业务文档审阅快照运行的 AI/规则审阅 | 建议只对该次固定输入有效，不能自动修改 |

### 4.1 文档类型与可编辑性

| 文档类型 | 查看 | 下载 | 直接编辑 | 可派生操作 |
| --- | --- | --- | --- | --- |
| 原件版本 | 是 | 是 | 否 | 抽取、转换模板、对比、只读智能审阅 |
| 临时上传对比文件 | 是 | 按权限 | 否 | 仅对比或只读智能审阅 |
| 模板历史/已发布版本 | 是 | 是 | 否 | 创建模板新草稿；已发布可填写模板可用于新建业务文档 |
| 业务文档 | 是 | 是 | 当前内部编辑人或有效外部填写会话可以 | 抽取、对比、智能审阅、删除 |
| 业务文档审计快照 | 仅在审批时间线或任务证据中查看 | 按审计权限 | 否 | 仅用于重放、证明和差异计算 |

## 6. 全局业务规则

### 6.1 不可变与版本规则

- 原件、正式模板版本、业务文档审计快照和批准结果均不可原地修改。
- 模板自动保存只写入短期编辑会话，显式“保存为新版本”才产生模板版本。
- 业务文档只有一份当前内容，不向用户显示版本号；自动保存和手动保存都更新该业务文档。
- 业务文档提交、驳回、批准、抽取、对比和智能审阅时，系统自动生成不可编辑的内部审计快照。
- 审计快照不能由用户恢复为业务文档；需要重新开展业务时，必须从已发布模板新建另一份业务文档。
- 模板恢复历史内容必须创建新模板版本，不允许将当前指针直接回退并覆盖历史。
- 每个派生对象必须记录来源对象和来源版本。
- 模板发布新版本不得影响已经创建的业务文档。

### 6.2 异步任务规则

- 上传验证、预览、抽取、模板转换、PDF 渲染、权威对比和智能审阅均可以异步执行。
- 页面必须展示当前阶段、进度、开始时间和可理解的失败原因。
- 重试必须复用相同输入快照并记录新的尝试次数，不能生成重复业务结果。
- 技术失败与人工驳回必须使用不同状态和文案。
- 用户刷新或重新登录后能够恢复任务状态。

### 6.3 编辑和并发规则

- 同一模板草稿或业务文档同一时刻只允许一个用户持有编辑租约。
- 业务文档同一时刻只能有一个可编辑主体：内部编辑人或外部链接填写人，二者不能同时存在。
- 业务文档保存必须携带内部内容校验标识；检测到内容已变化时禁止静默覆盖，但该标识不作为用户可见版本号。
- 失去租约、权限被撤销或流程已被他人处理时，页面切换为只读并允许用户复制未提交内容。
- 模板和业务文档分别使用独立编辑会话，不能交叉写入。

### 6.4 审计规则

以下动作必须记录操作者、时间、工作区、对象、基础版本或业务文档快照、结果和请求 ID：

- 登录、退出和权限变更。
- 上传、验证、下载和删除申请。
- 抽取创建、重试、字段修改、批准和驳回。
- 模板转换、编辑会话、保存、发布和恢复。
- 业务文档创建、保存、提交、转交编辑、审批转交、驳回、批准、传阅、取消和删除。
- 外部链接创建、访问、提交、撤销和重新开放。
- 对比创建、导出、批注和保存调整。
- 智能审阅、建议接受/忽略和 AI 对话。

审计日志不得保存文档正文、完整敏感字段、对象存储地址、签名 URL、模型密钥或内部提示词。

## 7. 功能需求

## 7.1 身份认证与会话

### 7.1.1 登录

- 用户使用邮箱和密码登录。
- 邮箱进行规范化处理；错误提示不能泄露邮箱是否注册。
- 登录成功后颁发 Bearer Token，并查询当前用户和当前工作区信息。
- Token 仅保存在当前浏览器标签页的 `sessionStorage`。

### 7.1.2 会话恢复与退出

- 访问受保护页面但会话失效时，跳转登录页并保存原工作区路径。
- 登录成功且仍有权限时返回原路径；无权限时进入工作台并提示原因。
- 退出登录只清除当前标签页会话，不删除服务端业务数据。
- 多标签页之间不共享登录状态。

### 7.1.3 验收要点

- 无 Token、无效 Token、过期 Token 和成员关系失效均不能访问业务数据。
- 登录恢复不得形成开放重定向。
- 退出后浏览器后退不能再次显示敏感页面内容。

## 7.2 工作台

### 7.2.1 我的待办

工作台左侧以卡片或列表聚合：

- 抽取复核待办。
- 业务文档填写/处理待办。
- 外部提交复核待办。
- 只读传阅。
- 失败任务和可重试事项。

卡片至少显示文档名称、任务类型、当前状态、发起人、更新时间、截止时间；抽取任务额外显示整体置信度。时间在一天内显示相对时间，超过一天显示明确日期和时间。

卡片主按钮应直接对应当前可执行动作，例如“去复核”“去填写”“查看传阅”“处理失败”。

### 7.2.2 数据概览

- 处理文档数。
- 抽取成功任务数和成功率。
- 待复核数量。
- 已批准抽取结果数。
- 已发布模板数。
- 流转中和已完成业务文档数。
- 字段准确率和平均处理时长。

统计必须显示时间范围。字段准确率只使用已经人工批准的数据，未复核结果只能展示置信度，不能计入准确率。

### 7.2.3 快捷操作

- 上传原始文档。
- 创建抽取任务。
- 进入复核队列。
- 新建业务文档；该快捷操作进入与业务文档列表相同的创建向导，由用户选择模板、内部/外部模式、编辑人和审批人。
- 新建文档对比。
- 发起智能审阅。

## 7.3 文档资产

### 7.3.1 上传范围

- 支持 `.doc`、`.docx`、`.pdf`。
- 单文件最大 10MB。
- 浏览器计算 SHA-256，并通过预签名地址直传对象存储。
- 服务端验证扩展名、真实 MIME、大小、摘要、对象 ETag、空文件和恶意内容。
- DOC 在隔离环境转换；DOCX 校验 ZIP、OOXML、路径穿越、宏、OLE、外部关系和远程资源；PDF 校验文件结构、加密和可解析性。

### 7.3.2 上传流程

```text
选择文件 -> 本地校验/计算摘要 -> 上传 staging -> 服务端确认
-> 安全验证 -> 固化不可变原件 -> 生成 PDF 预览 -> 可用
```

上传失败、安全校验失败和预览失败必须分别提示。预览失败不改变已经通过安全验证的原件内容；用户仍可在权限允许时下载原件或重试预览。

### 7.3.3 原件版本

- 一个逻辑文档可以包含多个原件版本。
- 上传新版本必须由用户明确选择目标逻辑文档，不能仅凭文件名自动覆盖或合并。
- 每个版本显示文件名、格式、大小、摘要、上传人、上传时间、版本号和处理状态。
- 每个版本可以独立发起抽取、模板转换、对比和智能审阅。
- 只有 `ready` 状态显示“智能抽取”“转换为模板”“文档对比”“智能审阅”操作；其他状态显示当前阻断原因和可执行的重试动作。
- 用户从原件详情点击“转换为模板”后进入模板创建弹窗，任务进度同时显示在原件详情和模板中心。

### 7.3.4 查看和检索

- 原件使用安全 PDF 或页图预览，永远只读。
- 支持缩放、翻页、页面跳转、文本搜索和下载。
- 文档列表支持分页、文件名搜索、格式、状态、上传人和时间筛选。
- 无权限的文档不出现在搜索结果中。

### 7.3.5 状态

```text
uploading -> verifying -> previewing -> ready
                       \-> validation_failed
              previewing -> preview_failed -> retrying
```

原件状态不承载抽取或模板转换进度；这些进度显示为独立任务。

## 7.4 抽取方案

### 7.4.1 字段能力

支持 `string`、`number`、`integer`、`boolean`、`date`、`datetime`、`object` 和 `array`。字段可以配置：

- 唯一 `key` 和 JSON Path。
- 展示名称和业务描述。
- 必填、nullable、字面量默认值。
- 枚举、格式、正则、数值边界、长度边界。
- 数组项类型和嵌套对象结构。
- 敏感等级、展示掩码和字段查看权限。
- 抽取提示、示例和未找到时的处理方式。

默认值只能是受类型约束的字面量，不允许表达式或脚本。没有配置默认值且未找到内容时返回 `null` 并说明原因，不能让模型猜测。

### 7.4.2 版本和发布

- 用户创建抽取方案草稿并实时校验。
- 发布后形成不可变方案版本，只有已发布版本可以用于正式抽取。
- 修改已发布方案时创建新草稿和新版本。
- 已发布版本可以另存为可复用模板。
- 历史抽取任务固定引用当时版本，不随最新版本变化。
- 版本可以归档，但被历史任务引用的版本不得物理删除。

### 7.4.3 状态

`draft -> published -> archived`

## 7.5 数据安全策略

### 7.5.1 内置识别范围

- 首期覆盖 CN、US、JP、KR、DE、FR、GB、AU、NL。
- 支持电话、邮箱、身份证件、护照、银行账户、姓名、位置及可配置业务敏感词。
- 使用 Presidio、RE2 安全正则、词典和受控 Validator。

### 7.5.2 安全处理流程

1. 解析文档并识别敏感明文。
2. 将同一任务中的同一敏感值替换为稳定令牌。
3. Java API 加密保存令牌映射。
4. 模型只接收令牌化文本、必要版面上下文和抽取方案。
5. 对模型输出再次执行 PII、未知令牌、证据和 Schema 校验。
6. 只允许恢复原文中已经存在的受控令牌值。
7. 按角色返回明文或掩码。

敏感识别服务不可用、发现明文泄露或未知令牌时，任务必须失败或进入安全复核，不能绕过检测调用模型。

### 7.5.3 策略管理

- 管理员按工作区启用国家、数据类型和自定义规则。
- 自定义正则必须符合 RE2 方言并限制复杂度。
- 词典限制大小，Validator 只能从允许列表中选择。
- 策略按不可变版本发布，任务固定引用版本。

## 7.6 智能抽取与人工复核

### 7.6.1 可选输入

- 已就绪的原件版本。
- 当前业务文档；创建任务时系统自动固化一份内部抽取快照。
- 用户新上传并完成验证的原件版本。

模板主要用于生成业务文档，不作为默认抽取入口。原件和新上传文件不能直接转换成业务文档，业务文档必须从已发布的 `fillable` 模板创建。

### 7.6.2 创建任务

用户必须选择一个原件版本或业务文档，并选择已发布抽取方案版本；可以选择敏感规则方案版本。系统在创建时固定：

- 原件版本，或业务文档抽取快照和摘要。
- 抽取方案版本。
- 敏感规则版本。
- 解析器、模型和 Prompt 版本。
- 创建人、工作区和幂等键。

同一文档可以多次抽取，不同任务互不覆盖。

### 7.6.3 执行流程

```text
排队 -> 解析 -> 敏感检测/令牌化 -> Schema 约束抽取
-> 输出/证据/PII 校验 -> 受控敏感值恢复 -> 待人工复核
```

失败时必须显示失败阶段、是否可重试和不包含敏感明文的诊断信息。

### 7.6.4 复核界面

- 左侧显示原件 PDF，并支持证据高亮和定位。
- 中间显示字段树或结构化 JSON。
- 右侧显示当前字段的值、来源、置信度、候选值、证据和操作记录。
- 敏感字段按权限显示明文或掩码。
- 字段值来源标记为 `extracted`、`default` 或 `manual`。

每个字段支持：

- 接受抽取值。
- 从候选值中选择。
- 手工修改并填写原因。
- 标记“原文未找到”。
- 标记“需要进一步确认”。

字段修改后必须重新通过类型、Schema、证据和敏感信息校验。

### 7.6.5 批准和驳回

- 所有必填字段必须处理完成后才能批准。
- 无证据字段不得以“AI 已确认”方式自动通过，只能由人工明确处理。
- 批准后形成不可变批准结果，可查看和导出 JSON。
- 驳回整份结果时必须填写原因；用户可以基于相同输入重新创建任务。
- 批准和驳回请求必须具备幂等保护。
- 默认由具有复核权限的用户完成字段处理和最终批准；启用双人模式后，最后修改字段的复核人只能提交批准申请，另一位具有批准权限的用户完成最终批准。

### 7.6.6 状态

```text
queued -> parsing -> extracting -> validating -> review_required
                                              -> reviewing -> approved
                                                           -> rejected
queued/parsing/extracting/validating -> failed -> retrying
```

## 7.7 模板中心

### 7.7.1 模板创建

- 用户在 `文档资产 -> 原件详情 -> 指定 ready 版本` 点击“转换为模板”。
- 创建弹窗要求填写模板名称、用途说明和模板类型，并可选择导入一个已发布抽取方案作为初始字段定义。
- 用户确认后，系统创建模板转换任务；任务在原件详情和模板中心均可查看。
- 转换成功后，系统自动创建模板逻辑对象和模板草稿，并向发起人发送站内通知；通知和任务结果提供“去编辑模板”入口。
- 转换成功不代表模板发布，用户仍需编辑、绑定字段、保存模板版本、通过质量检查并手动发布。
- 同一原件版本的同一次转换请求必须幂等；失败可以重试，失败不产生可发布模板版本。
- 同一原件已成功转换后再次点击时，页面优先提供“查看已生成模板”和“复制为新模板”操作，避免重复转换。
- 转换成功后如需创建业务变体，应复制模板创建新的模板草稿，而不是覆盖原模板。
- 模板必须记录来源原件版本。

模板转换任务状态：

```text
queued -> converting -> draft_ready
    |          |
    +----------+-> failed -> retrying
queued -> cancelled
```

### 7.7.2 DOC/DOCX 模板

- DOC 在隔离环境转换为工作 DOCX，原始 DOC 不变。
- DOCX 使用自托管原生文档编辑服务打开。
- 支持字符级富文本、分页、页眉页脚、表格、图片、列表、分节和页面设置。
- 编辑服务通过短期下载 URL、JWT、会话 nonce 和签名回调保存。
- 回调文件必须重新进行大小、ZIP、OOXML、路径穿越、宏、OLE、外部关系和恶意内容校验。

### 7.7.3 PDF 模板

- PDF 正文和原始页面保持不可变。
- 模板设计者可以在页面坐标层创建文本、日期、数字、单选、复选、图片和签名占位区域。
- PDF 模板不承诺任意正文重排或高保真转回 DOCX。

### 7.7.4 字段绑定

模板字段可以从创建模板时选择的抽取方案导入，也可以由模板设计者在模板编辑器中单独创建。导入只复制字段定义到模板草稿，抽取方案后续变更不会自动改变模板。

DOCX 中，模板设计者选择文字、占位内容或光标位置后创建 Content Control；PDF 中，模板设计者框选页面区域后创建坐标字段。`${name}` 等文本占位符可以被识别并辅助转换为正式字段，但不能作为发布后的唯一字段事实源。

每个绑定至少包含：

- 系统绑定 ID。
- 字段 key 和 JSON Path。
- 展示名称和数据类型。
- 是否必填、默认值和校验规则。
- 敏感等级和字段权限。
- Content Control ID/Tag 或 PDF 页码/坐标。
- 锁定策略和缺失处理策略。
- 同一字段多处出现时的同步关系。

未知、重复、丢失、被改写或非法嵌套的绑定必须阻断发布。

模板按字段能力分为：

- `fillable`：至少包含一个有效字段绑定，可以在新建业务文档时选择。
- `reference`：不包含填写字段，仅用于查看、下载、对比或继续设计，不能用于创建业务文档。

模板发布前必须明确模板类型；`fillable` 模板的字段定义、绑定关系和校验规则随模板版本一起冻结。

### 7.7.5 保存模板版本

“保存为新版本”执行以下完整事务链：

```text
强制保存 -> 下载编辑结果 -> 文件安全校验 -> 字段绑定校验
-> 创建并固化不可变版本 -> 生成 PDF 快照 -> 生成派生文档模型
-> 计算结构 Diff -> 质量检查 -> ready
```

任一步失败都不得替换当前可用版本。编辑器自动保存只保存短期工作副本，不产生正式版本。

### 7.7.6 发布、归档和恢复

- 只有 `ready`、PDF 快照成功、字段绑定有效且没有阻断告警的版本可以发布。
- 发布后的 `fillable` 版本可以在业务文档创建向导中选择；`reference` 版本不可创建业务文档。
- 模板发布成功不会自动创建业务文档，只更新模板的可用状态并提供“新建业务文档”手动入口。
- 模板发布新版本不影响已有业务文档。
- 恢复历史版本时复制历史内容创建新草稿，完成检查后作为新版本发布。
- 模板版本不可直接删除；可以归档并停止新建业务文档。

### 7.7.7 模板状态

```text
模板草稿：creating -> editing -> committing -> committed
              |          |
              +----------+-> failed

模板版本：rendering -> checking -> ready -> published -> superseded / archived
                  |          |
                  +----------+-> failed / blocked
```

## 7.8 文档生成

### 7.8.1 创建入口

- 模板发布成功后不会自动生成业务文档。
- 用户在 `文档协作 -> 业务文档` 点击“新建业务文档”。
- 模板详情可以提供“新建业务文档”快捷入口，但仍需由用户手动确认，并进入同一个创建向导。

### 7.8.2 创建向导

1. 选择一个已发布且类型为 `fillable` 的模板版本。
2. 输入业务文档名称和业务元数据。
3. 可选预填写模板字段。
4. 选择唯一处理模式：内部编辑或外部编辑。
5. 内部编辑模式必须选择一位初始编辑人和至少一位审批人；审批人可以配置为有顺序的多级列表。
6. 外部编辑模式必须选择至少一位内部审批人，并配置链接有效期、访问码和暂存规则。
7. 用户确认后，系统创建业务文档，将模板字段和内容实例化为该文档的当前内容，并固定引用创建时的模板版本。

内部模式创建成功后，系统向初始编辑人生成编辑待办；外部模式创建成功后，系统生成唯一有效的外部填写链接。两种模式互斥，不能同时创建内部编辑待办和外部编辑链接。

模板后续升级可以在业务文档详情提示，但不得自动改变现有业务文档。用户需要使用新模板时，应重新创建另一份业务文档。

### 7.8.3 填写方式

- 默认在浏览器渲染的文档页面中将字段锚点表现为可聚焦、可点击的输入区域，尽可能实现原位置填写。
- 无法稳定内联输入的字段使用点击后弹出的输入框或字段面板填写。
- 同一字段绑定到多处时，任一位置填写后同步更新全部位置。
- 表单显示必填、类型、枚举、格式、敏感掩码和错误提示。
- 外部填写页面不暴露完整模板编辑器，只开放被授权字段。
- 日常内部和外部填写页面均不嵌入模板 POC 编辑器，主要通过文档原位置字段、弹层或字段面板完成结构化填写。
- 当前内部编辑人从“对比并调整”或“智能审阅”进入正文调整时，可以打开受控原生编辑会话；该能力不能改变来源模板，也不能开放给外部填写人或审批人。
- 表单值和文档字段锚点必须保持双向同步：表单修改更新文档内容，允许的文档字段编辑也要更新结构化字段值。

### 7.8.4 保存和导出

- 自动保存和点击“保存”都更新同一份业务文档，不生成业务版本号。
- 每次保存携带内部内容校验标识；检测到陈旧内容时阻止覆盖并要求刷新。
- 提交、驳回和批准时，系统在改变流程状态前自动生成不可编辑的审计快照。
- 支持导出当前有权访问的业务文档 DOCX/PDF；PDF 模板生成填写后的 PDF。
- 导出文件必须显示业务文档名称、导出时间和当前流程状态，不展示业务版本号。

## 7.9 文档协作与待办流转

### 7.9.1 发起方式

业务文档在创建时必须选择且只能选择一种编辑模式：

- 内部编辑：指定一位系统用户作为当前编辑人，并配置一个或多个顺序审批人。
- 外部编辑：生成无需登录的填写链接，并配置一个或多个顺序审批人。

一份业务文档同一时刻只能有一个可编辑主体。内部编辑模式不能生成外部填写链接；外部编辑模式不能创建内部编辑待办。传阅和普通查看不属于编辑主体，可以并行存在。

### 7.9.2 内部待办访问

- 根据待办 ID 请求详情时，服务端必须校验当前登录人是否为处理人或有管理/查看权限。
- 编辑待办的当前处理人可以取得编辑租约并填写或修改文档。
- 审批待办的当前处理人只能查看提交审计快照、审批意见和业务文档当前内容，不能修改正文或字段。
- 其他有查看权限的用户只能看到当前已保存内容和处理状态。
- 待办被处理、转交或权限失效后，原处理页面必须立即变为只读。

### 7.9.3 编辑人动作

| 动作 | 结果 |
| --- | --- |
| 保存草稿 | 保存当前内容，不结束待办 |
| 提交审批 | 校验字段、保存当前内容、生成提交审计快照，关闭编辑待办并创建第一位审批人的只读审批待办 |
| 转交编辑 | 保存当前内容，关闭当前编辑待办并创建另一位系统用户的编辑待办 |
| 传阅 | 创建只读传阅任务，不转移当前主待办的处理权 |

转交编辑时必须选择一个有效工作区用户，可以附加说明和截止时间。不能转交给审批链中的停用用户，也不能在未保存当前内容时静默丢弃修改。

### 7.9.4 审批人动作

审批人不能修改业务文档正文和字段，可以执行：

| 动作 | 结果 |
| --- | --- |
| 批准 | 生成批准审计快照；存在下一审批人时创建下一审批待办，最后一人批准后完成流程 |
| 驳回 | 必须填写原因，生成驳回审计快照，关闭当前审批链并将业务文档退回当前指定编辑人 |
| 转交审批 | 将当前审批待办转交给另一位有审批权限的系统用户，不改变审批顺序中的其他节点 |
| 传阅 | 创建只读传阅任务，不改变当前审批待办和审批顺序 |

业务文档被任一审批人驳回后重新进入内部编辑状态。编辑人修改并再次提交时，审批链从第一位审批人重新开始，确保所有审批人审核的是同一次提交内容。

### 7.9.5 传阅

- 传阅人选择一个或多个系统用户。
- 创建传阅时系统固化只读传阅快照；被传阅人只能查看该快照并确认已阅。
- 被传阅人不能编辑、驳回、通过、转交或继续传阅。
- 传阅不改变主流程当前处理人和状态。
- 主流程结束后未读传阅仍可以在有效期内查看；是否自动关闭由发起人设置。

### 7.9.6 驳回和再次提交

- 驳回必须填写原因，并固定驳回时的审计快照。
- 内部模式退回当前指定编辑人；外部模式按审批人选择重新开放原链接或生成新链接。
- 内部编辑人或外部填写人修改并保存同一份业务文档后再次提交。
- 历史提交快照、审批结果和驳回意见保持可见，但不形成用户可编辑或恢复的版本对象。

### 7.9.7 流程完成

- 最后一位审批人批准后，流程进入完成状态。
- 系统保存最终批准审计快照、锁定业务文档当前内容并生成最终 PDF/DOCX。
- 已完成文档只读，不允许继续编辑；需要开展新的业务时，用户从已发布模板重新创建一份业务文档。
- 发起人和有权限的参与人可以查看完整时间线。

### 7.9.8 编辑并发

- 内部模式仅当前编辑待办处理人可以持有编辑租约；审批期间没有内部用户可以编辑。
- 外部模式仅有效链接对应的填写会话可以编辑；内部用户只能查看和管理链接。
- 保存携带内部内容校验标识；冲突时提示刷新或先进入文档对比，不能静默覆盖。
- 断线时保留本地未提交提示，不能假定保存成功。
- 编辑租约超时后可由当前编辑人重新获取；管理员强制释放必须审计。

### 7.9.9 删除业务文档

- 草稿且尚未发起编辑/审批的业务文档可以由创建人或管理员删除。
- 存在内部编辑或审批待办时，必须先取消流程，关闭全部活动待办后才能删除。
- 存在外部填写链接时，删除操作先撤销链接并使所有外部会话失效。
- 已完成业务文档删除后进入回收站；审批记录和审计快照按工作区保留策略继续保存。
- 删除后的文档不能继续编辑、提交、审批、对比调整或智能审阅，但有审计权限的管理员仍可查看必要记录。
- 最终物理清理由管理员按数据保留策略执行。

### 7.9.10 状态

```text
业务文档：draft -> editing_internal -> awaiting_approval -> completed
                    |                   |
                    |                   +-> rejected -> editing_internal / editing_external
                    +-> editing_external -> awaiting_approval
                    +-> cancelled -> deleted / recycled

编辑待办：pending -> editing -> submitted | transferred | cancelled
审批待办：pending -> approved | rejected | transferred | cancelled

传阅：unread -> read | expired
```

“驳回”是流转动作，不是业务文档终态；内部模式退回编辑人，外部模式重新开放填写，之后重新进入完整审批链。

## 7.10 外部链接填写

### 7.10.1 创建链接

外部编辑模式在新建业务文档向导中创建链接。发起人必须配置：

- 有效期。
- 是否允许暂存。
- 最大填写尝试次数。
- 是否启用访问码。
- 允许填写和查看的字段范围。
- 一个或多个有顺序的内部审批人。

系统生成不可枚举的高强度随机链接令牌。一份业务文档同一时刻只能有一个有效的可编辑外部链接，也不能同时存在内部编辑待办。业务文档创建成功后，链接在业务文档列表和详情页提供“复制链接”操作；页面和日志不得暴露内部对象存储地址。

### 7.10.2 外部填写流程

```text
打开有效链接 -> 校验访问码/状态 -> 查看必要上下文
-> 填写字段 -> 暂存或提交 -> 保存提交审计快照并关闭编辑链接
-> 按顺序进入内部审批 -> 最后一位批准完成
-> 任一审批人驳回时重新开放原链接或生成新链接
```

- 外部用户不需要系统账号。
- 页面必须明确显示链接有效期、隐私说明和提交结果。
- 提交前校验全部必填和格式规则。
- 重复提交请求必须幂等，刷新结果页不能产生第二次提交。
- 发起人可以随时撤销链接。
- 外部用户提交后，该填写轮次立即关闭，不允许继续修改；审批驳回后才会创建新的填写轮次。
- 链接过期、撤销、达到尝试上限、业务文档等待审批或已经完成后均不可继续填写。

外部链接只证明令牌持有人完成了填写，不等同于实名认证或电子签名。

### 7.10.3 外部提交复核

- 外部提交后为第一位审批人创建只读审批待办，不允许审批人直接修改正文。
- 审批按创建业务文档时配置的顺序逐级执行；最后一位审批人批准后完成流程。
- 任一审批人驳回时必须填写原因，并选择重新开放原链接或生成新链接；业务文档返回外部编辑状态。
- 重新填写和保存继续更新同一份业务文档；历史提交内容只保留为内部审计快照。
- 发起人或管理员可以在审批完成前取消流程并撤销链接，但必须记录原因。

### 7.10.4 状态

```text
active -> submitted_closed -> approved
   |              |
   |              +-> rejected -> reopened / replaced
   +-> expired / revoked
```

## 7.11 文档对比

### 7.11.1 功能目标

用户能够选择任意两份自己有权访问的文档，查看可定位、可筛选、可审计的差异；当其中存在当前用户负责编辑的内部业务文档时，可以从“对比并调整”入口修改该业务文档并直接保存当前内容。

### 7.11.2 三种来源组合

系统必须完整支持：

1. 上传两份新文档进行对比。
2. 上传一份新文档，并从系统中选择一份文档进行对比。
3. 从系统中选择两份文档进行对比。

每个选择槽位均支持“上传文件”或“从系统选择”。系统文档选择器支持：

- 原件版本。
- 模板版本。
- 业务文档当前内容。

上传文件支持 DOC、DOCX、PDF，必须先完成安全校验并创建临时不可变原件版本，再进入对比。临时版本的保留周期按工作区策略执行。

### 7.11.3 创建对比

对比入口包括：

- “文档对比”中心的“新建对比”。
- 原件或模板详情的“与其他文档对比”，该入口只提供“仅对比”。
- 业务文档详情的“仅对比”和“对比并调整”两个明确入口。
- 业务文档编辑器中的“查看与指定基线的差异”。

1. 用户选择文档 A，作为基线文档。
2. 用户选择文档 B，作为比较文档。
3. 页面显示双方类型、来源、原件/模板版本号或业务文档快照时间、更新时间和可编辑性。
4. 用户选择“仅对比”或“对比并调整”。
5. 系统验证双方权限、文件状态和编辑目标。
6. 创建任务时固定双方内容摘要和算法版本；若一侧是业务文档，系统自动创建只读对比快照。
7. 后台完成解析、统一模型转换和权威 Diff。

文档 A/B 的方向在任务创建后不得互换；用户可以显式点击“交换双方”重新创建任务。

### 7.11.4 仅对比模式

- 两侧始终只读，即使用户对业务文档拥有编辑权限。
- 用户可以切换并排视图、统一视图和仅差异视图。
- 用户可以筛选差异类型、逐项导航、查看详情、添加批注和导出报告。
- 查看对比不会修改任何文档；业务文档仅在任务创建时生成内部对比快照。

### 7.11.5 对比并调整模式

只有满足以下条件时可启用：

- 至少一侧是内部编辑模式的业务文档。
- 当前用户正是该业务文档的当前编辑待办处理人。
- 业务文档状态为 `editing_internal`。
- 用户能够取得编辑租约。

可编辑性规则：

| 对象 | 是否可作为调整目标 | 处理方式 |
| --- | --- | --- |
| 上传的新文件 | 否 | 只作为对比输入，不创建可编辑业务文档 |
| 原件版本 | 否 | 永远只读 |
| 模板版本 | 否 | 对比页不可修改；需要修改时单独创建模板新草稿 |
| 内部编辑中的业务文档 | 是 | 仅当前编辑人取得租约后可编辑，保存更新同一份业务文档 |
| 外部编辑中的业务文档 | 否 | 只能由外部链接填写人编辑 |
| 等待审批的业务文档 | 否 | 审批期间正文只读 |
| 已完成业务文档 | 否 | 只读；需要新业务时从模板重新创建文档 |

- 只有一侧可编辑时，系统自动将其设为调整目标并明确标识。
- 两侧均为可编辑业务文档时，用户必须选择唯一调整目标。
- 两侧均不可编辑时，“对比并调整”禁用并解释原因。
- 进入方式决定权限语义：从“仅对比”进入时整个页面只读；从“对比并调整”进入且校验通过时才显示编辑和保存操作。

### 7.11.6 对比维度

权威 Diff 至少支持：

- 文本插入、删除和替换。
- 段落、标题、列表等块结构变化。
- 内容移动。
- 字体、字号、粗斜体、颜色、对齐、缩进和行距等格式变化。
- 表格新增/删除、行列变化和单元格内容变化。
- 图片新增/删除、替换和位置变化；无法识别内容时显示为对象变化。
- 页眉页脚、页面尺寸、方向、分节和显式分页变化。
- 模板字段绑定变化。
- 业务文档字段值变化，并按 JSON Path 聚合。

不同格式之间的对比以统一中间模型为准。PDF、扫描件或复杂浮动版式无法达到结构级精度时，系统必须标记可靠性和转换告警，不能制造误导性的精确结论。

### 7.11.7 对比结果页面

- 默认左侧文档 A、右侧文档 B。
- 删除内容使用红色和“已删除”文字；新增内容使用绿色和“已新增”文字；修改和移动使用独立图标/标签，颜色不能作为唯一信号。
- 顶部显示双方来源、原件/模板版本或业务文档快照时间、对比模式、任务状态、差异总数和告警。
- 支持同步/独立滚动、缩放、页码/节点跳转和折叠任一侧。
- 差异列表支持按文本、结构、格式、表格、图片、字段和页面设置筛选。
- 点击差异项同时定位双方对应位置。
- 没有差异时明确显示“在当前算法和支持范围内未发现差异”。
- 支持在权威差异项上添加批注、回复和解决。
- 支持导出包含双方来源和固定输入信息、差异摘要、详细差异和告警的对比报告。

### 7.11.8 调整与保存

- 调整目标一侧显示原生编辑器或受控字段编辑能力，另一侧保持只读。
- 用户可以手工编辑；对可安全映射的文本或字段变化，可以逐项选择“应用到调整目标”。
- 系统必须明确变化应用方向，例如“将 A 的内容应用到 B”。
- AI 风险解释只作为建议，不能自动应用。
- 编辑过程中前端可以计算实时草稿 Diff，并明确标记“草稿差异，尚未保存”。
- 草稿 Diff 不进入权威审计，不得冒充服务端最终结果。
- 用户点击保存后，系统进行内容冲突和编辑租约检查，更新同一份业务文档并记录审计事件。
- 保存成功后，系统生成新的只读对比快照，服务端重新创建或确认权威 Diff，并将页面切换到最新结果。
- 原对比任务、原双方快照和调整前结果必须保留，但不形成用户可编辑或恢复的版本对象。

### 7.11.9 对比状态

```text
queued -> validating -> parsing -> comparing -> completed
             |           |          |
             +-----------+----------+-> failed -> retrying
queued/validating -> cancelled
```

对比结果处理状态可以另行标记为 `unreviewed`、`reviewed`、`adjusted` 或 `dismissed`，不改变权威计算状态。

### 7.11.10 异常和边界处理

- 文件损坏、加密或带密码时停止处理并提示更换文件。
- 一侧转换失败时不生成部分权威结论，允许修复后重试。
- 用户在任务执行中失去权限时终止结果访问，后台任务按安全策略取消或完成但不可见。
- 调整目标被其他用户锁定时仍可只读对比，但不能进入编辑。
- 调整目标内容已被其他会话改变时，保存必须提示冲突，允许刷新后以最新内容重新比较。
- 超出浏览器实时 Diff 容量时降级为“保存后生成权威 Diff”。
- 两个内容摘要相同的输入仍可创建对比，但系统可以直接给出相同提示并保留任务记录。

### 7.11.11 对比验收标准

- 三种来源组合均可成功创建任务，并显示双方准确来源、原件/模板版本或业务文档快照时间。
- 两份上传文档只读对比，不出现保存入口。
- 上传加业务文档只有在当前用户是该内部业务文档编辑人时才能进入“对比并调整”。
- 系统中的原件或模板作为任意一侧时始终不可被覆盖。
- 两份系统业务文档均可编辑时必须选择唯一目标。
- “仅对比”入口即使面对可编辑业务文档也不允许修改。
- 保存调整更新同一份业务文档，不产生业务版本号；调整前后的内部快照均保留。
- 权威 Diff 可通过双方原件/模板版本或业务文档快照以及算法版本重放。
- 复杂格式无法可靠比较时展示明确告警。

## 7.12 智能审阅与 AI 文档助手

### 7.12.1 名称和范围

一级功能名称为“智能审阅”，右侧对话组件名称为“AI 文档助手”。智能审阅不仅检查文字错误，还支持文档理解、归纳、统计和基于文档的问答。

### 7.12.2 输入范围

- 用户新上传的文档。
- 系统原件版本。
- 模板版本。
- 业务文档当前内容。

新上传文件先成为不可变原件。上传文件、原件和模板始终只读，不能由智能审阅入口创建业务文档。业务文档只有在内部编辑模式、当前用户是编辑待办处理人并取得编辑租约时可修改；外部编辑、等待审批和已完成状态均只读。

### 7.12.3 页面布局

- 左侧显示文档内容。
- 不可编辑文档使用 PDF/页图预览。
- 可编辑业务文档使用原生编辑器或受控字段编辑器。
- 右侧使用 AI 对话框，展示默认审阅结果和后续对话。
- 点击 AI 返回的证据或建议时定位左侧对应内容。

### 7.12.4 默认智能审阅

进入详情后，系统针对固定输入自动创建一次默认审阅任务；业务文档作为输入时先生成只读智能审阅快照。默认检查：

- 错别字和拼写。
- 语法和标点。
- 术语和表达一致性。
- 编号、日期、金额和前后引用的一致性。
- 可能缺失、重复或自相矛盾的内容。

每条建议至少包含类别、严重程度、问题说明、原文位置、证据、修改建议和任务所依据的原件/模板版本或业务文档快照时间。无法定位的建议只能作为一般提示，不能提供“一键应用”。

### 7.12.5 AI 对话

用户可以继续要求：

- 总结文档大意或指定章节。
- 提取、归纳和分类文档信息。
- 统计文档中的数字、日期、主体或条目。
- 根据文档数据生成可展示的表格或图表。
- 解释某段内容或比较文档内部表述。
- 继续检查特定术语、格式或业务规则。

回答必须基于当前任务快照，并尽可能附带可定位证据。模型不知道或文档中没有的信息必须明确说明，不能伪造来源。

AI 消息支持普通文本、Markdown 表格、结构化统计数据以及可渲染的柱状图、折线图和饼图。图表必须显示数据来源和对应文档证据，支持导出；将表格或图表插入可编辑业务文档时必须由当前编辑人确认，保存后仍更新同一份业务文档。

### 7.12.6 建议处理和保存

- 用户可以接受、忽略或添加备注。
- 上传文件、原件和模板只能复制建议，不能直接应用或创建业务文档。
- 对可编辑业务文档，接受建议前必须展示实际替换内容。
- 每次批量应用前显示变更清单，用户确认后再写入草稿。
- 保存更新同一份业务文档，不产生业务版本号；原审阅快照的未处理建议标记为“内容已变化”。
- 用户可以针对最新内容重新运行审阅，系统生成新的审阅快照。
- 所有问题处理完成后可以标记“审阅完成”。

### 7.12.7 安全规则

- 智能审阅和 AI 对话复用抽取链路的敏感令牌化和输出二次扫描。
- 模型只接收当前用户有权处理的文档内容。
- 对话历史按工作区和任务所使用的原件/模板版本或业务文档审阅快照隔离。
- 文档内容和对话不得默认用于供应商训练。
- AI 建议必须标识为建议，不能替代法律、财务或合规判断。

### 7.12.8 状态

`queued -> analyzing -> review_required -> completed`，异常状态为 `failed`、`cancelled`、`outdated`。

## 7.13 批注、通知和审计查询

### 7.13.1 批注

- 业务文档和权威对比结果支持批注线程。
- 业务文档批注锚定创建时的审计快照、节点、文本范围、原文引号和上下文；对比批注锚定权威对比结果。
- 支持回复、解决和重新打开。
- 内容变化后无法可靠重新定位时显示“需重新定位”，不能静默挂错位置。

### 7.13.2 站内通知

- 新待办、转交、驳回、传阅、外部提交、任务失败和批注回复产生站内通知。
- 通知点击后跳转到有权限的具体对象。
- 权限已失效时不显示历史敏感内容，只说明资源不可访问。

邮件、短信和即时通讯通知不作为首期必选能力，可以后续通过通知通道扩展。

### 7.13.3 审计查询

- 管理员按操作者、动作、对象类型、对象 ID、结果和时间范围查询。
- 普通用户只查看自己有权限对象的业务时间线。
- 审计记录追加写入，不允许普通用户修改或删除。
- 导出审计记录时继续执行字段掩码和权限校验。

## 8. 关键端到端流程

### 8.1 原件到批准数据

```text
登录 -> 上传原件 -> 服务端验证 -> 生成预览
-> 选择抽取方案/安全策略 -> 异步抽取
-> 字段复核 -> Schema 再校验 -> 批准 -> 导出正式 JSON
```

### 8.2 原件到发布模板

```text
原件详情选择 ready 版本 -> 点击“转换为模板” -> 创建转换任务
-> 转换成功并创建模板草稿 -> 进入模板编辑器
-> 导入/创建字段并绑定 Content Control 或 PDF 坐标
-> 保存模板新版本 -> 安全/绑定/PDF/结构检查
-> 用户手动发布 -> fillable 模板进入业务文档创建向导的可选列表
```

### 8.3 模板到内部完成文档

```text
业务文档列表点击“新建” -> 选择已发布 fillable 模板
-> 选择内部编辑 -> 指定编辑人和有顺序的审批人
-> 创建业务文档和编辑待办 -> 编辑人填写/保存同一份文档
-> 提交并生成审计快照 -> 审批人依次批准或驳回
-> 最后一位批准 -> 锁定当前内容 -> 生成最终 DOCX/PDF -> 完成
```

### 8.4 模板到外部提交

```text
业务文档列表点击“新建” -> 选择已发布 fillable 模板
-> 选择外部编辑 -> 指定有顺序的内部审批人和链接规则
-> 创建业务文档并生成唯一外部链接 -> 在列表/详情复制链接
-> 外部用户填写/保存/提交 -> 关闭填写并生成审计快照
-> 审批人依次批准 -> 完成
-> 任一审批人驳回 -> 重新开放原链接或生成新链接 -> 再次填写
```

### 8.5 文档对比并调整

```text
选择/上传文档 A 和 B -> 选择“对比并调整”
-> 验证当前用户是唯一业务文档目标的内部编辑人
-> 固化双方对比快照并生成权威 Diff
-> 用户查看并调整 -> 保存同一份业务文档
-> 固化调整后快照并重算权威 Diff -> 标记已调整
```

### 8.6 智能审阅并修订

```text
选择业务文档 -> 固化审阅快照 -> 自动智能审阅
-> 查看证据/继续对话 -> 当前编辑人人工接受或忽略建议
-> 保存同一份业务文档 -> 重新生成审阅快照并审阅 -> 完成
```

## 9. 状态与动作一致性

| 场景 | 可以继续处理 | 允许编辑 | 保存或快照结果 |
| --- | --- | --- | --- |
| 原件 ready | 是 | 否 | 只能上传新原件版本 |
| 抽取 review_required | 是 | 仅复核字段 | 批准时产生正式结果 |
| 模板草稿 editing | 是 | 持锁时可以 | 提交后创建模板新版本 |
| 模板版本 ready | 是 | 否 | 可以发布或基于其创建新草稿 |
| 模板 published | 可以创建业务文档 | 不直接编辑 | 基于其创建新草稿 |
| 业务文档 editing_internal | 是 | 当前编辑人且持锁时可以 | 保存更新当前内容；提交产生审计快照 |
| 业务文档 editing_external | 是 | 仅有效外部填写会话 | 保存更新当前内容；提交产生审计快照 |
| 业务文档 awaiting_approval | 是 | 否 | 批准/驳回产生审计快照 |
| 业务文档 completed | 只读查看 | 否 | 需要新业务时从模板重新创建 |
| 对比 completed + 仅对比 | 是 | 否 | 不修改文档，只保留对比快照 |
| 对比 completed + 调整 | 是 | 当前内部编辑人可编辑唯一目标 | 保存更新同一份业务文档并生成前后快照 |
| 智能审阅 review_required | 是 | 仅当前内部编辑人可应用建议 | 保存更新同一份业务文档并使旧建议过期 |

## 10. 错误、空状态与恢复

### 10.1 通用错误展示

错误信息必须回答：发生在哪个阶段、是否影响已有数据、用户能否重试、下一步可以做什么。不得只显示内部错误码。

### 10.2 任务恢复

- 上传中断可以重新选择相同文件恢复或重传。
- 异步任务失败后可以从安全检查点重试。
- 模板编辑服务故障不能丢失上一正式模板版本；业务文档编辑故障不能丢失最后一次成功保存的当前内容。
- PDF 渲染失败时模板版本保留但禁止发布。
- 对比失败不修改任何输入文档。
- AI 审阅失败不影响文档查看和人工编辑。
- 外部链接过期后只能由发起人延长、重新开放或生成新链接。

### 10.3 空状态

- 无文档时提供上传入口。
- 无抽取方案时引导创建方案，不能进入空任务页面。
- 无已发布模板时解释必须先完成模板发布。
- 无待办时显示可执行的快捷操作。
- 对比无差异时显示双方原件/模板版本或业务文档快照时间，以及算法支持范围。
- 智能审阅无问题时说明检查范围和所依据的版本或审阅快照，不使用绝对正确性表述。

## 11. 非功能需求

### 11.1 安全

- 对象存储保持私有，查看和下载使用短期鉴权地址。
- 所有对象按工作区隔离并执行对象级权限检查。
- 密码只保存安全单向哈希；模型密钥使用 Secret/KMS 加密。
- 编辑服务自托管在受控网络，回调验证 JWT、nonce、来源主机和顺序。
- 禁止宏执行、危险 OLE、远程模板和未批准插件。
- 敏感令牌映射和字段结果加密保存。
- 日志、监控和错误消息不记录正文与敏感明文。

### 11.2 性能与容量

- 支持 10MB 以内 DOC、DOCX、PDF。
- 常见文档解析与抽取 P95 不超过 2 分钟。
- 常见 DOCX 编辑会话创建 P95 不超过 10 秒。
- 长任务必须异步执行并持续反馈阶段状态。
- 前端实时 Diff 超出容量阈值时自动降级，不阻塞编辑输入。

### 11.3 可用性与无障碍

- 关键状态同时使用颜色、文字和图标表达。
- 上传、字段跳转、差异导航、建议接受/忽略和提交支持键盘操作。
- 页面刷新后恢复服务端状态。
- 所有危险或不可逆业务动作要求确认并说明影响对象。
- 时间、来源类型、当前权限，以及适用时的原件/模板版本号或业务文档快照时间在详情页保持可见。

### 11.4 数据保留

- 原件版本、模板版本、批准结果、业务文档审计快照和审计记录按工作区保留策略保存。
- 删除默认进入回收站并延迟清理；被流程、任务或审计引用的对象不能立即物理删除。
- 临时上传、编辑工作副本和失败 staging 文件按配置自动清理。
- 模型输入输出只保留满足诊断和审计的最小必要周期。

## 12. 指标口径

| 指标 | 计算方式 |
| --- | --- |
| 处理文档数 | 时间范围内进入 ready 的唯一原件版本数 |
| 抽取成功率 | 成功进入 `review_required` 的抽取任务数 / 有效抽取任务数 |
| 字段准确率 | AI 原始字段值与最终批准字段值按规范化规则比较的正确字段数 / 已批准字段总数 |
| 待复核量 | 当前用户有权限且状态为 `review_required/reviewing` 的任务数 |
| 平均流转时长 | 流程创建到完成的平均耗时 |
| 驳回率 | 发生过至少一次驳回的流程数 / 已处理流程数 |
| 对比调整率 | 保存过业务文档调整的对比任务数 / 已查看对比任务数 |
| AI 建议接受率 | 被接受建议数 / 已处理建议数；不把未处理计入分母 |

## 13. 全功能验收场景

### 13.1 身份和权限

- 用户登录、会话过期恢复原路径、退出后不能读取缓存敏感页面。
- 不同工作区用户无法通过猜测 ID 访问文档、任务、待办和对比结果。
- 无敏感权限用户始终看到掩码。

### 13.2 原件与抽取

- DOC、DOCX、PDF 上传、验证、预览、下载和失败重试完整可用。
- 同一逻辑文档可新增原件版本，旧版本不变。
- 同一原件可多次选择不同抽取方案执行任务。
- 抽取结果能够逐字段定位证据、复核、修改、批准和驳回。

### 13.3 模板

- DOC/DOCX 转为可编辑模板，保存形成 DOCX、字段清单、PDF 快照和派生模型。
- PDF 保留原页面并可配置坐标字段。
- 模板字段既可以从抽取方案导入，也可以在模板编辑器创建；字段随模板版本冻结。
- Content Control 或坐标字段校验失败时禁止发布。
- `reference` 模板不可用于创建业务文档，只有已发布 `fillable` 模板出现在创建向导中。
- 模板修改和恢复均产生新版本，原件和历史版本摘要不变。

### 13.4 生成和流转

- 用户从业务文档列表手动新建，选择已发布 `fillable` 模板和内部/外部唯一模式；模板发布不会自动创建业务文档。
- 内部模式指定编辑人 A 和顺序审批人 B、C；A 编辑并提交，B 批准后 C 才收到审批待办，C 批准后完成。
- 审批人不能修改正文；B 驳回后文档退回 A，A 修改同一份文档并重新提交，审批链从 B 重新开始。
- 自动保存和手动保存均更新同一份业务文档，产品界面不展示业务版本号。
- 提交、批准、驳回、对比和智能审阅产生只读审计快照，快照不能被用户编辑或恢复。
- 传阅用户只能查看和确认已阅，不影响主待办。
- 内部编辑待办和外部填写链接不能同时存在，内容校验冲突不会静默覆盖。
- 完成后的业务文档保持只读；需要再次办理时从模板重新创建另一份文档。
- 草稿、进行中和已完成业务文档分别按照取消流程、撤销外链和回收站规则删除。

### 13.5 外部填写

- 有效链接可以填写、暂存和提交。
- 过期、撤销或达到上限的链接不能访问内容。
- 外部提交关闭填写并为第一位审批人创建只读待办；顺序审批完成后业务文档完成。
- 审批驳回可以重新开放原链接或生成新链接，重新填写仍更新同一份业务文档。
- 重复点击提交不会产生重复审计快照或重复待办。

### 13.6 文档对比

- 上传两份文件完成只读对比。
- 上传一份文件和系统原件完成只读对比。
- 上传一份文件和内部编辑中的业务文档完成对比并调整，保存后更新同一份业务文档。
- 两份系统文档完成对比；当两份均可编辑时必须选择唯一目标。
- 原件和模板在任何对比组合中均不可被覆盖。
- 仅对比、实时草稿 Diff 和服务端权威 Diff 的标识明确且不会混淆。
- 业务文档对比任务固定输入快照，保存调整后生成新快照并重算权威 Diff，但不产生业务版本号。
- 文本、结构、格式、表格、字段和页面变化可以筛选和定位。

### 13.7 智能审阅

- 进入详情自动运行默认审阅并返回带位置的建议。
- 用户可以继续摘要、统计和问答，并渲染、导出带证据的表格和图表。
- 上传文件、原件和模板没有编辑入口；只有当前内部编辑人可以对业务文档应用建议。
- 保存建议修改更新同一份业务文档，原审阅快照的建议明确标记为内容已变化。
- 模型请求、响应和日志通过敏感明文零泄露测试。

## 14. 发布依赖与质量门禁

全功能可以分阶段交付，但必须按以下依赖顺序通过门禁：

1. 基础门禁：鉴权、工作区隔离、原件不可变、对象存储和审计可用。
2. 抽取门禁：Schema、敏感令牌化、证据、人工复核和批准闭环通过。
3. 模板门禁：原生编辑器 G0 还原度、授权、安全回调、Content Control、PDF 快照和版本状态机通过。
4. 协作门禁：业务文档单一当前内容、内容冲突保护、审计快照、编辑/审批待办、内外部互斥、外部链接、删除和最终锁定通过。
5. 对比门禁：三种来源组合、权威 Diff、业务文档快照、调整目标权限和保存当前内容通过。
6. 智能审阅门禁：证据定位、敏感保护、人工确认、图表输出和保存当前内容通过。

任何后续功能不得绕过前一阶段的不变性、权限和安全约束。

## 15. 已确定的产品决策

- 文档对比完整支持“两份上传、一份上传加一份系统文档、两份系统文档”。
- 对比入口区分“仅对比”和“对比并调整”，进入方式决定页面是否允许编辑。
- 对比调整永远只有一个业务文档目标，原件、上传临时文件和模板版本不可直接编辑。
- 业务文档只能从已发布 `fillable` 模板手动创建，不允许从原件、上传文件或智能审阅入口创建。
- 模板保存产生新模板版本；业务文档保存、对比调整和 AI 建议应用均更新同一份业务文档，不产生用户可见版本号。
- 业务文档在提交、驳回、批准、抽取、对比和智能审阅时生成只读内部审计快照。
- 模板字段正式使用 Content Control 或 PDF 坐标层；`${name}` 只可作为导入识别或兼容提示，不作为唯一事实源。
- 模板字段可以从已发布抽取方案导入，也可以在模板编辑器创建；只有包含有效字段的 `fillable` 模板可以创建业务文档。
- 文档填写优先提供文档原位置交互，无法稳定内联时使用弹层或字段面板，不阻断流程。
- 新建业务文档时必须选择内部或外部唯一编辑模式，并配置一个编辑人（仅内部）和一个或多个顺序审批人。
- 审批人不能修改正文，只能批准、驳回、转交审批或传阅；驳回后审批链从第一位重新开始。
- 传阅是只读旁路，不接管主流程。
- 外部提交必须进入顺序审批；驳回后重新开放原链接或生成新链接。
- 业务文档删除采用取消活动流程、撤销外链、进入回收站和按保留策略清理的规则。
- “智能纠错”正式命名为“智能审阅”，聊天区域命名为“AI 文档助手”。

## 16. 完成定义

当本 PRD 所列身份与权限、原件资产、抽取与复核、模板创建与发布、业务文档手动创建、内部编辑与顺序审批、外部填写、三种来源文档对比、对比并调整、智能审阅、审计快照、删除、安全和异常恢复均通过验收场景后，DocMind 才达到“全功能流程闭环”。

单个页面可演示、AI 能返回结果或编辑器能够打开，都不等同于完成；完成必须以原件/模板版本或业务文档快照输入明确、权限正确、失败可恢复、结果可确认、业务文档只有一份当前内容且关键节点可审计为准。
