# 产品需求文档 v0.1

状态：Draft  
目标：完成“Word 原件 -> 安全 JSON + 可人工确认的 HTML 模板”闭环。

## 1. 对象与边界

| 对象 | 定义 | 是否可编辑 |
| --- | --- | --- |
| 原件 | 用户导入的 DOCX/PDF 文件及其只读预览 | 否 |
| 抽取 Schema | 用户定义的 JSON 字段约束 | 是，变更后生成新版本 |
| Schema 模板 | 用户保存的可复用字段定义模板 | 是，复制后生成新版本 |
| 抽取结果 | 按 Schema 返回的 JSON、证据、默认值和复核状态 | 仅可通过复核操作修改 |
| 模板 | 由原件转换、经人工微调后的受控 HTML 结构 | 是 |
| 模板实例 | 基于模板填写具体业务数据后的文档 | v0.2 |

原件和模板的左右对照不是系统自动判定的文档 Diff，而是转换质量的人工校验：左侧只读原件预览，右侧模板预览/编辑，用户确认格式与文字是否需要微调。

## 2. 用户故事

- 作为文档处理员，我可以上传 DOCX/PDF，查看不可编辑的原件预览和处理进度。
- 作为文档处理员，我可以定义 JSON 字段的 `key`、描述、类型、必填性、默认值和敏感级别。
- 作为文档处理员，我可以得到符合字段定义的 JSON，并查看每个字段的值来源、原文证据和置信度。
- 作为文档处理员，我可以查看 Word 转换出的 HTML 模板，边看原件边微调模板后保存。
- 作为管理员，我可以追踪谁上传、解析、修改字段或保存模板。

## 3. 功能需求

### 3.1 Word 导入与原件预览

接受 DOCX/PDF；单文件最大 10MB。校验扩展名、真实 MIME、文件大小、空文件和恶意内容。解析必须保留或尽力识别图片、表格、页眉页脚和目录；无法保留的版式记录转换告警。原始对象按版本不可变保存，生成只读 PDF 或页图用于浏览器预览。原件预览永远不提供编辑入口。

### 3.2 JSON 字段定义

用户以表单创建字段，系统保存为版本化 Schema；高级用户可查看/导入受限 JSON Schema。Schema 可以另存为 Schema 模板，创建抽取任务时选择已有模板或新建字段。字段定义如下：

```json
{
  "key": "party_a_credit_code",
  "description": "合同甲方的统一社会信用代码",
  "type": "string",
  "required": false,
  "default": null,
  "sensitivity": "high"
}
```

`key` 在同一 Schema 内唯一；`default` 可以是空字符串，但必须能通过字段类型校验。未找到、无足够证据或模型无法确认时，如果用户配置了默认值则返回该默认值并记录 `value_source=default`，否则返回 `null` 并记录原因；不得将模型猜测写入最终值。发现多个候选值时不自动选择，返回候选证据并进入人工复核。

### 3.3 敏感信息保护与结构化抽取

应用层使用 Microsoft Presidio 的 Analyzer/Anonymizer 作为框架，配合 `libphonenumber` 做国内外手机号识别、`email-validator`/标准规则识别国内外邮箱、内置及自定义 Recognizer 识别中国身份证和其他证件格式。用户可在设置中维护自定义敏感规则，并保存为敏感规则模板，在任务中选择关联。每个命中的原文值替换为稳定令牌，例如 `[[SENSITIVE:PHONE:01]]`；令牌到原文值的映射加密保存，仅任务执行上下文可读取。大模型只接收脱敏文本、字段 Schema 和必要版面上下文。

模型必须返回严格 JSON 和令牌/非敏感值。应用层执行 JSON Schema 校验、证据校验和敏感令牌回填：只允许将已存在的令牌恢复为原件中对应的敏感值，禁止模型生成或改写敏感值。若字段要求敏感值但没有有效令牌，返回默认值并要求复核。自定义规则优先采用正则、词典或校验器，不使用 LLM 判断是否敏感。

### 3.4 抽取结果与复核

每个字段记录 `value`、`value_source`（`extracted/default/manual`）、`evidence`、`confidence`、`needs_review`、模型和 Prompt 版本。用户可接受、修改或驳回；人工修改保留旧值、新值、原因、操作者和时间。证据缺失的字段不可自动审批。

### 3.5 模板转换、校验与微调

后端先用确定性 DOCX/OOXML 解析生成中间文档模型，再转换为白名单 HTML 和样式。模板由块、行内文本、表格、图片、页码提示和占位符组成，禁止存储可执行脚本。转换完成后进入“原件-模板校验”工作台：左侧原件只读，右侧模板可切换预览/编辑。用户微调后保存为新模板版本，并明确标记其基于的原件版本。

## 4. 验收标准

- 同一原件版本、Schema 版本和敏感规则模板版本重复提交时任务可幂等处理。
- 文件仅允许 DOCX/PDF，单文件不超过 10MB；测试样例覆盖图片、表格、页眉页脚和目录。
- 模型请求和模型日志中不得出现原件中的身份证号、手机号或邮箱明文；敏感回填只能来自加密映射。
- 每个最终字段均有 `value_source`；找不到值时有默认值则返回默认值，否则返回 `null`，不能返回空泛模型文本。
- 多个候选值必须进入人工复核，系统不能静默选取其中一个。
- 每个抽取字段可定位到原件页码/段落/文本片段；无证据字段不能自动批准。
- 原件在左右校验视图中不可编辑；模板编辑不修改原始 Word。
- 模板保存后生成新版本，原模板仍可查看和回滚。
- 10MB 以内常见 DOCX/PDF：解析和抽取任务 95 分位不超过 2 分钟；常见字段黄金集准确率目标 >= 90%。

## 5. 完成定义

开发完成时应具备可演示的 DOCX/PDF 上传、敏感脱敏抽取、字段复核、HTML 模板转换与左右人工校验全链路，并使用固定 Mock 文档和自动化脱敏样例通过泄露、失败重试、权限和 API 契约测试。MVP 验收前由产品侧补充真实脱敏文档并建立黄金数据集，完成准确率和证据命中率评测。模板实例填写与文档 Diff 在后续版本实现。
