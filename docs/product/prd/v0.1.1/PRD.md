# 产品需求文档 v0.1.1

状态：Draft  
前置版本：v0.1 工程验收通过  
目标：解决 Word 模板分页、页眉页脚和字符级格式还原不足，以及当前段落选择式微调不符合富文本编辑习惯的问题。

## 1. 核心决策

模板不再以安全 HTML 作为唯一事实源。每个原生编辑模板版本必须同时拥有以下表示：

| 表示 | 责任 | 是否事实源 |
| --- | --- | --- |
| 不可变原件 | 审计、追溯、左侧对照 | 是，不可修改 |
| 可编辑 DOCX | DOC/DOCX 模板的版式和正文 | 是 |
| 字段绑定清单 | Schema 字段、JSON Path 与 Content Control 的映射 | 是 |
| PDF 快照 | 固定分页预览、验收和视觉回归 | 是，针对该版本不可变 |
| 受控文档模型/安全 HTML | 抽取、搜索、结构 Diff 和旧页面兼容 | 否，由事实源派生 |

PDF 模板采用“原始 PDF + 页面坐标字段层”，不要求转换为 DOCX 后编辑。

## 2. 用户故事

- 作为模板设计者，我可以在保留 Word 分页、页眉页脚、字体和表格结构的页面中直接选择文字并编辑，而不是从段落下拉框逐段修改。
- 作为模板设计者，我可以把光标位置或选择范围绑定为一个 Schema 字段，并明确看到字段 key、JSON Path、敏感级别和锁定状态。
- 作为审核者，我可以左侧查看不可变 PDF 原件，右侧查看或编辑工作 DOCX，并按页比对。
- 作为管理员，我可以追踪模板编辑会话、字段绑定、保存、发布、回滚和转换告警。
- 作为系统，我可以在文档编辑服务不可用或保存失败时保留上一稳定版本，不能产生半版本或覆盖原件。

## 3. 功能需求

### 3.1 DOC/DOCX 高保真编辑

系统必须使用自托管文档编辑服务打开工作 DOCX。编辑区域至少支持文字选择、输入法、撤销重做、字体、字号、颜色、背景色、粗体、斜体、下划线、段落对齐、缩进、行距、列表、表格、图片、显式分页、纸张尺寸、页边距、页眉页脚和页码。

DOC 原件先在隔离转换环境生成工作 DOCX；原件对象和摘要不变。编辑器保存结果只能成为模板新版本，不能覆盖原件或已有模板版本。

### 3.2 分页与预览

左侧始终使用服务端布局引擎生成的 PDF。右侧编辑器使用打印布局展示真实页面边界、页间距和页眉页脚。每次模板版本提交后异步生成新的 PDF 快照；快照就绪前版本状态为 `rendering`，不能发布。

系统必须记录页面尺寸、方向、节、首页/奇偶页页眉页脚、页数、使用字体和字体替代告警。缺少字体、未支持图形、分页差异、损坏字段或外部资源必须形成可定位告警。

### 3.3 富文本交互

右侧编辑采用光标和选择范围语义。工具栏状态必须反映当前选择；混合格式显示混合态。用户可以直接编辑正文、页眉页脚和表格，不需要从“编辑段落”下拉框选择节点。

左右栏继续支持拖拽、折叠、独立滚动、页码跳转和缩放。同步滚动按页码或布局锚点近似定位，不承诺按像素同步。

### 3.4 字段绑定

DOCX 字段使用 Content Control 表示。每个控件必须有不可重复的系统 ID，并在 Tag 中包含受控引用，不存放敏感值。字段清单至少保存：

- `binding_id`
- `schema_version_id`
- `schema_field_id`
- `field_key`
- `json_path`
- `value_type`
- `sensitivity`
- `content_control_id`
- `content_control_tag`
- `lock_policy`
- `missing_behavior`

保存时后端必须读取并校验 DOCX 中的 Content Control：未知、重复、丢失、Tag 被修改、绑定 Schema 不匹配或控件嵌套非法时阻断发布。用户可选择锁定控件本身、仅允许填写内容或允许模板设计者修改。

### 3.5 编辑会话与版本

打开编辑器时创建短时编辑会话，绑定用户、工作区、模板、基础版本、文档 key、到期时间和权限。编辑服务通过受控下载 URL 获取工作文件，通过签名回调提交保存结果。

“保存为新版本”必须执行：强制保存 -> 下载编辑结果 -> 文件安全校验 -> Content Control 校验 -> 对象存储落盘 -> 创建不可变版本 -> PDF 渲染 -> 结构/字段 Diff -> 版本就绪。任一步失败都不得更新模板当前版本。

发布仅允许 `ready`、无阻断告警且字段清单校验通过的版本。回滚继续采用“基于历史版本创建新的发布版本”，不修改历史记录。

### 3.6 PDF 模板

PDF 继续按原始页面展示。模板设计者可以在页面上创建文字、日期、复选框、图片和签名等字段区域；字段以页码和坐标保存。v0.1.1 不提供任意 PDF 正文重排、原字体段落编辑或 PDF 转 DOCX 后的高保真回写。

### 3.7 安全和部署

文档编辑服务必须自托管并部署在受控网络中。文件下载和保存回调使用 JWT、短时 URL、会话 nonce 和工作区权限；对象存储不得公开。回调返回的下载地址只允许来自配置的编辑服务主机，防止 SSRF。

禁用或拒绝宏、可执行 OLE、外部模板、远程图片、危险关系和未允许的插件。日志只记录 ID、摘要、状态和告警，不记录文档正文或字段敏感值。

## 4. 验收标准

### 4.1 功能验收

- 用户可在右侧直接选择部分文字，独立修改字体、字号、颜色和粗体，不影响同段其他 Run。
- A4/Letter、横竖版、显式分页、多节、首页/奇偶页页眉页脚、表格、图片和页码可以显示、编辑、保存并重新打开。
- 每次保存生成新 DOCX 和 PDF 快照；原件、基础版本和历史版本摘要不变。
- 字段控件可插入、定位、修改标签、删除和重新校验；非法绑定不能发布。
- 编辑服务中断、重复回调、回调乱序和保存超时不会产生重复版本或半版本。

### 4.2 还原度门禁

建立不少于 30 份合法脱敏的 DOC/DOCX 版式集，覆盖中英文/CJK 字体、颜色、字号、粗斜体、列表、表格跨页、图片、页眉页脚、分节和纸张方向。以原件在约定参考引擎生成的 PDF 为基线：

- 正文不得丢失、重复或乱序，字段控件不得丢失。
- 支持集内页数一致率达到 95% 以上；不一致必须产生告警。
- 支持能力清单逐项通过率 100%；未支持元素必须有明确降级或阻断告警。
- 版本重新打开后的字段绑定保留率 100%，DOCX 保存后再次渲染不出现阻断差异。
- 每份文档同时执行页面图像回归和人工检查；自动指标只做筛选，不替代人工发布确认。

### 4.3 性能与可用性

- 10MB 以内常见 DOCX 的编辑会话创建 P95 不超过 10 秒；首次打开和服务端渲染分别记录独立指标。
- 保存操作必须显示 `saving/rendering/ready/failed` 状态，用户刷新后可以恢复状态。
- 文档编辑服务不可用时左侧原件、历史版本和抽取功能仍可使用，右侧显示可恢复错误。

## 5. 完成定义

v0.1.1 完成时，DOC/DOCX 用户能够在 Word 风格分页编辑器中进行字符级富文本编辑、插入系统字段并保存为不可变版本；PDF 使用原始页面和坐标字段层；版本均具备可编辑文件、字段清单、PDF 快照、告警和审计。旧 HTML 模板仍可查看和回滚，并有显式升级入口。全部功能通过还原度、权限、回调安全、幂等、故障恢复和浏览器 E2E 门禁后，才允许启动 v0.2 实例与批注实现。
