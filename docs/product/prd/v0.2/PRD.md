# 产品需求文档 v0.2

状态：Draft  
目标：把已发布模板安全地填写为可提交的文档实例，并提供可追溯的批注和人工确认的文字纠错。

## 1. 范围与边界

本版本建立在 v0.1 已发布模板之上，只处理模板实例的填写、保存、提交、批注和纠错；不包含任意两份文档的 Diff。原件仍然只读，模板的后续版本不会改变既有实例。

| 对象 | 定义 | 是否可编辑 |
| --- | --- | --- |
| 模板实例 | 从固定模板版本创建的业务文档 | 草稿/保存状态下可编辑 |
| 实例版本 | 每次创建、保存、提交或恢复产生的不可变快照 | 否 |
| 批注线程 | 锚定在实例版本文本范围上的讨论 | 可回复、可解决 |
| 纠错建议 | 由规则或 AI 生成、等待人工处理的建议 | 可接受或忽略 |

## 2. 用户故事

- 作为业务人员，我可以从已发布模板创建实例，填写字段和可编辑正文，保存草稿并提交。
- 作为审阅人，我可以对具体文本添加批注、回复和解决批注，而不会丢失被批注的上下文。
- 作为业务人员，我可以获得拼写、语法、标点、风格和术语建议，并逐条决定接受或忽略。
- 作为协作者，我可以实时看到谁正在编辑、最后保存的内容和锁状态，不会静默覆盖他人的提交。

## 3. 功能需求

### 3.1 实例填写与版本

用户只能从已发布的模板版本创建实例；实例固定关联该模板版本。字段占位符按字段绑定填写，文档正文只允许编辑受控节点。创建、保存、提交、恢复均生成不可变实例版本，保存和提交请求必须携带 HTTP `If-Match` 当前 `revision`；冲突时客户端必须刷新、比较或另存，不能覆盖。

实例状态为 `draft -> editing -> saved -> submitted -> archived`。提交后内容默认只读；具有退回权限的审阅人可以创建新草稿版本，不能修改已提交版本。每个版本记录操作者、时间、变更摘要、结构化 HTML 和填写数据快照。

### 3.2 编辑、保存和协作

同一实例同一时刻仅一人持有编辑租约。其他用户可实时只读查看已广播的受控内容操作和保存状态；网络中断、主动退出或租约超时后锁释放。服务端以 Redis 租约加数据库乐观锁双重保护，浏览器不能仅凭本地状态判断自己仍可保存。

编辑器复用 v0.1 的分页、表格、图片、页眉页脚、缩放和分栏能力。字段编辑控件必须显示必填、格式、枚举、敏感掩码和权限状态；敏感值默认掩码，仅有字段查看权限的用户可临时查看。

### 3.3 批注

批注必须锚定到节点 ID、文本范围、原文引号和前后上下文。内容编辑后系统先按节点与范围重挂载，失败时以引号与上下文提示用户重新定位，不能将批注静默挂到错误文字。线程支持创建、回复、解决和重新打开；批注、解决人、时间和关联实例版本均进入审计记录。

### 3.4 智能文字纠错

纠错包括拼写、语法、标点、风格和术语。规则型检查优先在应用层运行；需要 AI 的检查必须执行与抽取相同的敏感令牌化和模型输出二次 PII 扫描，不能将实例明文直接发送给外部模型。建议包含文本锚点、类别、严重程度、原因和可选替换文本；系统不得自动改写正文，用户逐条接受或忽略后才生成新的实例版本。

术语词典按工作区管理，支持禁用词、推荐写法和忽略词；纠错结果只对创建时的实例版本有效，正文有变化时必须重新定位或重新运行。

## 4. 验收标准

- 从同一模板版本创建的实例不会受模板新版本影响，且每次保存/提交都有可恢复快照。
- 并发保存产生 `revision` 冲突而非静默覆盖；锁超时和断线可恢复。
- 批注在普通编辑后能正确重挂载，无法重挂载时明确显示“需重新定位”。
- AI 纠错请求、响应和日志中敏感明文泄露率为零；建议不能自动应用。
- 已提交实例不可直接修改，退回后的编辑生成新版本并保留提交审计。

## 5. 完成定义

用户可基于 v0.1 发布模板创建实例、填写和保存/提交，审阅人可完成批注闭环，用户可安全地处理纠错建议；版本、锁、权限、敏感数据和审计都有自动化测试。
