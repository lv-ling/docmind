# 产品需求文档 v1.0

状态：Draft  
目标：提供可审计的文档版本比较，并在编辑时提供浏览器内的实时差异反馈。

## 1. 范围与边界

本版本支持以下三类比较组合：

1. 用户上传的 DOC/DOCX/PDF 与另一份上传文件；
2. 两个系统已保存版本（原件、模板版本或实例版本）；
3. 一份上传文件与一个系统已保存版本。

上传文件必须先成为临时只读原件版本；旧版 DOC 和 PDF 的解析/转换由后端异步处理。后端只保存不可变版本之间的权威 Diff。浏览器只对当前编辑草稿和已加载基线计算即时 Diff，该结果不作为审计记录，保存后由后端重新生成或确认权威 Diff。

## 2. 用户故事

- 作为用户，我可以选择或上传两个文档，看到左侧旧内容为红色、右侧新内容为绿色的并排结果。
- 作为模板/实例编辑者，我可以在编辑中实时看到相对指定基线的变化，并决定保存为新版本。
- 作为审阅人，我可以查看结构、文本、格式和字段数据的变化，对差异添加批注，并识别 AI 风险建议。

## 3. 功能需求

### 3.1 比较对象与可编辑性

比较选择器统一使用 `DocumentRef`：`source_version`、`template_version`、`instance_version`。上传文件完成校验后创建临时 `source_version`，因此“上传 + 已保存文档”与其他组合复用同一流程。

| 比较对象 | 后端处理 | 页面是否可编辑 | 保存目标 |
| --- | --- | --- | --- |
| 上传原件 / 原件版本 | 异步解析、转换、权威 Diff | 否 | 无 |
| 模板版本 | 结构化权威 Diff | 仅进入独立模板编辑工作台后可编辑 | 新模板版本 |
| 实例版本 | 结构化权威 Diff | 用户有编辑权且持有锁时可编辑 | 新实例版本 |
| 编辑中的实例草稿 | 前端实时 Diff | 是 | 新实例版本 |

原件永远不可编辑。用户不能在对比页面把变更写回旧版本；有权编辑的模板或实例必须通过独立编辑会话保存为新版本。

### 3.2 后端权威 Diff

后端先将上传原件转换为统一中间文档模型；系统版本直接使用受控文档模型。Diff 至少比较块结构、表格单元格、文本、格式和 JSON 字段路径，输出 `insert/delete/replace/format/move` 变化及双方锚点。上传比较为异步任务，状态为 `queued -> parsing -> comparing -> completed | failed`；保存的结果记录比较双方的不可变版本、算法版本、创建人和时间。

### 3.3 前端实时 Diff

前端在编辑器的 Web Worker 中对当前草稿与已加载基线运行增量结构化 Diff，使用节点 ID 优先、文本范围回退。实时 Diff 不调用 AI，不上传未保存内容，防止输入延迟与敏感泄露。编辑后 300ms 防抖刷新；超出浏览器容量阈值时降级为“保存后生成权威 Diff”。

实时结果只用于视觉提示，页面明确标注“草稿差异，尚未保存”。用户保存后用服务端版本结果替换草稿结果。

### 3.4 展示、审阅与无障碍

默认并排视图：左侧删除/旧内容使用红色与“已删除”文字标识，右侧新增/新内容使用绿色与“已新增”文字标识；颜色不得是唯一信息源。支持统一视图、仅显示差异、差异导航、同步/独立滚动、缩放、折叠面板和按页/节点定位。

字段变化按 JSON Path 聚合，格式变化显示属性前后值。用户可在权威 Diff 上创建批注；AI 风险解释仅作为“AI 建议”，必须附可定位证据，不能自动修改或替代用户判断。

## 4. 验收标准

- 三类比较组合均可创建任务并正确显示对象来源和可编辑性。
- 上传比较不允许编辑；模板/实例编辑不会覆盖任何旧版本或原件。
- 保存的 Diff 可从双方版本和算法版本重放；浏览器草稿 Diff 不被误标为权威结果。
- 左右视图能正确表达插入、删除、替换、格式和字段变化，并支持键盘逐项导航。
- 复杂格式无法可靠比较时显示范围和告警，而不制造误导性精确结论。

## 5. 完成定义

用户能完成上传、选择系统版本和混合来源的比较；编辑者能安全获得实时草稿差异；审阅结果、批注和权威版本 Diff 可复核、可审计。
