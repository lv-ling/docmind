# DocMind 文档中心

文档按“为什么做、做什么、怎么做、如何交付”组织。产品需求按产品版本冻结；技术方案以稳定基线为主，通过技术版本、变更记录和 ADR 管理演进。文档中的版本号遵循 `v0.x`（探索/MVP）、`v1.x`（稳定能力）和 `v2.x`（重大能力演进）。

## 版本规则

- `v0.1`：验证“Word 原件 -> 脱敏字段抽取 -> JSON 复核 -> HTML 模板人工校验”闭环。
- `v0.2`：加入模板实例填写、单人编辑锁、实时只读同步和结构化 HTML 对比。
- `v1.0`：加入上传 Word 异步对比、导出、权限、审计和生产质量门禁。
- 版本目录内的 PRD 是不可覆盖的快照；修改已发布版本时创建下一个版本或补丁说明。
- 技术文档默认维护 `architecture` 下的当前基线；只有不兼容的架构、数据模型、接口或事件变化才创建 `architecture/versions/` 技术版本。
- 技术文档的小幅实现调整记录在 ADR 或对应文档的变更记录中，不复制整个技术方案。
- 每个版本目录必须包含 `README.md`（版本目标、范围、变更、状态）和 `PRD.md`（详细需求）。

## 文档生命周期

`Draft` -> `Review` -> `Approved` -> `Implementing` -> `Released` -> `Archived`。

需求变更先更新对应版本的变更记录；如果影响 API、数据模型、权限或异步事件，必须同步架构/契约文档，并新增 ADR。已 Released 的版本不直接改写，通过新版本承接变化。

## 文档规则

- 需求变更先更新 PRD，再同步架构和接口契约。
- AI 输出必须保留来源片段、置信度、模型版本和提示词版本。
- 任何破坏性 API 或数据变更必须新增 ADR，并提供迁移方案。
