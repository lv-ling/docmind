# 本地基础设施

## 一键操作

在项目根目录执行：

```bash
# 启动基础服务、等待健康并初始化 MinIO bucket
./scripts/dev/infra.sh start

# 查看全部基础设施容器状态
./scripts/dev/infra.sh status

# 停止容器但保留数据卷
./scripts/dev/infra.sh stop

# 重启已有容器并等待恢复健康
./scripts/dev/infra.sh restart

# 配置变化后强制重建容器，不删除数据卷
./scripts/dev/infra.sh recreate
```

首次启动会拉取固定摘要的镜像、创建本地数据卷和四个 MinIO bucket，可能需要几分钟。`start` 会等待四个服务健康后才成功返回。

## 服务和凭据

| 服务 | 容器 | 地址 | 账号 | 密码 |
| --- | --- | --- | --- | --- |
| PostgreSQL | `docmind-postgres` | `localhost:5432` | `docmind` | `12345678` |
| Redis | `docmind-redis` | `localhost:6379` | 无 | `12345678` |
| RabbitMQ | `docmind-rabbitmq` | `localhost:5672` | `docmind` | `12345678` |
| RabbitMQ 管理台 | `docmind-rabbitmq` | <http://localhost:15672> | `docmind` | `12345678` |
| MinIO API | `docmind-minio` | <http://localhost:9000> | `minioadmin` | `12345678` |
| MinIO 控制台 | `docmind-minio` | <http://localhost:9001> | `minioadmin` | `12345678` |

这些密码只允许用于本地开发，不得用于测试或生产环境。配置来源是 [docker-compose.yml](../../deploy/compose/docker-compose.yml)；如需覆盖配置，将 `.env.example` 复制为同目录的 `.env`。所有端口只绑定 `127.0.0.1`，不会向局域网开放。

## 访问方式

```bash
# PostgreSQL
docker exec -it docmind-postgres psql -U docmind -d docmind

# Redis
docker exec -it docmind-redis redis-cli -a 12345678

# 查看 RabbitMQ 队列和容器日志
docker exec docmind-rabbitmq rabbitmqctl list_queues
docker logs -f docmind-rabbitmq
```

RabbitMQ 和 MinIO 更适合通过浏览器管理台访问；应用服务应使用容器外的 localhost 地址或 Compose 网络中的服务名访问。

四个服务完整的命令行、浏览器和应用连接示例见 [容器访问手册](../../deploy/compose/ACCESS.md)。

## 日常流程

1. 启动 Docker Desktop。
2. 确认本机没有其他 Redis/RabbitMQ 占用 `6379/5672/15672`；若使用 Homebrew，可执行 `brew services stop redis` 和 `brew services stop rabbitmq`（只停止服务，不删除数据）。
3. 首次使用先执行 Web 依赖安装和 Document AI 环境同步。
4. 在项目根目录执行 `./scripts/dev/start.sh`，由脚本启动并检查基础设施，再启动三个应用。
5. 修改 Compose 配置后使用 `./scripts/dev/infra.sh recreate`，而不是只执行 `restart`。
6. 开发结束先按 `Ctrl+C` 关闭三个应用，再执行 `./scripts/dev/infra.sh stop`；不要使用 `down -v`，否则会删除本地数据库和对象存储卷。

## 模板真实联调

DOC/DOCX 模板预览依赖 LibreOffice CLI 和目标语言字体。确认 `soffice` 可执行；如果它不在 `PATH`，用 `DOCMIND_LIBREOFFICE_COMMAND` 指定绝对路径。中文文档还需要安装可被 LibreOffice/Fontconfig 发现的 CJK 字体。DOC 的 Python 预转换可另用 `DOCMIND_AI_LIBREOFFICE_BINARY` 指定命令。

准备好 Web 依赖和 Document AI 虚拟环境后，在一个终端启动完整开发环境：

```bash
# 启动基础设施、Web、Server 和 Document AI
./scripts/dev/start.sh
```

随后在另一个终端执行完整 MVP 验收：

```bash
# 自动生成两页 DOCX，验收上传到模板发布和回滚的完整流程
./scripts/dev/e2e.sh mvp
```

脚本使用本地演示账号，生成确定性的两页敏感 DOCX，并验证 PostgreSQL V1-V13 迁移、MinIO 预签名上传和不可变原件、RabbitMQ 任务、Schema 与九国敏感规则、应用层令牌化、Mock 抽取、二次 PII 扫描、字段复核与审批、AI DOCX 解析、两页 PDF 与安全 HTML、模板 v1/v2/v3、后端 Diff、发布和回滚。成功时输出原件、抽取、Schema、规则和模板 UUID，以及字段数、版本数、PDF 字节数与告警数；数据会保留在本地工作区供 Web 页面复查。

如需逐个验证 DOC、DOCX、PDF，可准备三份已知页数的测试文件后执行：

```bash
# 使用指定样例逐一验证三种文件格式
./scripts/dev/e2e.sh source-formats \
  --doc /absolute/path/sample.doc \
  --docx /absolute/path/sample.docx \
  --pdf /absolute/path/sample.pdf
```

脚本要求每种格式完成真实对象存储上传、服务端摘要与 MIME 校验、不可变原件下载、PDF 预览和页数提取。若 `soffice` 不在 `PATH`，启动 API 前仍需设置 `DOCMIND_LIBREOFFICE_COMMAND`。
