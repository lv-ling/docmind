# MVP 路线图

## 阶段

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| M0 基础 | Monorepo、鉴权、工作区、DOCX/PDF 原件、对象存储、CI、契约包 | 能上传并安全预览不可编辑原件 |
| M1 安全抽取 | OOXML 解析、字段 Schema、敏感令牌化、JSON 抽取、证据、默认值、复核 | 明文敏感信息不出应用层，黄金集准确率达标 |
| M2 模板 | 中间文档模型、HTML 模板、原件-模板人工校验、模板版本 | 原件不可编辑，模板微调不影响原件 |
| M3 实例协作 | 基于模板创建实例、填写、保存/提交、单人编辑锁、实时只读同步 | 无静默覆盖，锁超时和网络冲突可恢复 |
| M4 文档对比 | Word 异步转换 Diff、模板/实例 HTML 精确 Diff、风险解释 | 明确区分两种对比的耗时和准确度 |

## 质量门禁

每个阶段必须通过单元测试、契约测试、关键链路 E2E、依赖漏洞扫描、权限矩阵测试和脱敏检查。上线前固定模型版本、Prompt 版本和解析器版本，建立回滚开关。

## 主要风险

- 复杂版式还原不稳定：先定义受控文档模型，保留原始预览作为对照。
- LLM 幻觉或格式错误：Schema + 证据校验 + 默认值策略 + 人工审批四重门禁。
- 敏感信息泄露：应用层令牌化、加密映射、模型请求/日志泄露测试和最小权限回填。
- 模板实例多人覆盖：Redis 租约锁、数据库 revision 校验、WebSocket 状态广播和失联超时回收。
- 大文件和长任务超时：分片上传、异步队列、阶段性进度和可重试。
- 多租户数据泄露：对象级鉴权、私有桶、租户隔离测试和审计告警。

## 已确认的开发配置

- 开发环境使用 Docker Compose 启动 PostgreSQL、Redis、RabbitMQ、MinIO；统一使用仅限本地开发的密码 `12345678`。
- 允许第三方模型处理脱敏后的输入；供应商、模型名和 API Key 由服务端设置项管理，通过 LangChain/LangGraph 适配，不绑定具体供应商。暂无模型时先使用 Mock Provider。
- 文档转换采用 LibreOffice headless 生成预览，DOCX 使用 OOXML 解析生成中间文档模型；PDF 使用文本/版面解析并按需 OCR。
- 测试文档由产品侧在系统完成后补充，开发先使用固定 Mock 文档和自动化脱敏样例。

## 后续决策

上线前仍需确定部署形态（单租户/多租户）、数据出境要求、保留周期和生产模型供应商。这些决定会影响成本、合规和数据模型，应记录为 ADR。
