## 技术版本规则

- `T0.1`：MVP 技术闭环，允许快速迭代。
- `T0.1.1`：替换模板核心编辑表示的兼容补丁；历史数据不原地迁移，以 ADR 和显式升级承接。
- `T0.2`：兼容性增强或新增服务能力，不要求复制全部文档；在当前基线中标注变化并记录 ADR。
- `T1.0`：接口、事件、数据迁移或部署方式达到稳定承诺。
- 只有发生不兼容变化时，才在 `versions/T*.md` 创建快照；快照必须附迁移和回滚方案。
- API 的 `/api/v1` 是接口契约版本，不等同于产品 PRD 版本或技术基线版本。

## 判断是否需要新技术版本

需要新技术版本：删除/重命名公开 API、改变事件语义、破坏数据兼容、替换文档核心模型、改变租户隔离方式。无需新版本：新增内部实现、性能优化、Prompt 调整、增加可选字段；这些进入 ADR、CHANGELOG 或评测记录。
