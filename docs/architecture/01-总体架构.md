# 总体架构

技术基线：T0.1  
适用产品：PRD v0.1  
状态：Draft

## 多应用仓库目录基线

```text
docmind/
├── apps/docmind-web/          Vue 3；独立 Node 工具链及 Web 内部模块
├── apps/docmind-server/       Java 17；独立 Maven Wrapper 及业务契约
├── apps/docmind-document-ai/  Python；独立 uv 锁及模型输出契约
├── tests/e2e/                 无第三方依赖的跨应用黑盒验收
├── docs/                      产品、架构、设计、开发和交付文档
├── deploy/                    Compose、观测与环境样例
└── scripts/                   无依赖的开发与验收编排脚本
```

三个应用可分别复制为独立仓库：Web 持有前端契约类型、编辑器和 UI 模块；Server 持有 OpenAPI、事件与业务 JSON Schema；Document AI 持有模型输出 JSON Schema。应用之间不共享源码包、依赖锁或构建配置。Document AI 服务不能直接访问浏览器、业务数据库、对象存储或敏感映射。

## 目录职责与依赖

| 目录 | 职责 | 可依赖 | 禁止依赖 |
| --- | --- | --- | --- |
| `apps/docmind-web` | 用户界面、浏览器状态、前端契约、编辑器和 UI | 自身 Node 依赖、Server HTTP API | 其他应用源码、数据库、对象存储、AI 模型 SDK |
| `apps/docmind-server` | 业务领域、权限、持久化、脱敏、编排、业务契约 | 自身 Maven 依赖、Document AI HTTP API | Web 页面与其他应用源码 |
| `apps/docmind-document-ai` | 文档解析、脱敏后的抽取、验证和评测 | 自身 Python 依赖 | 其他应用源码、业务数据库、原件存储、敏感映射 |
| `deploy` | 环境、编排、观测配置 | 构建产物 | 业务源码副本 |
| `tests/e2e` | 跨应用黑盒验收 | 公开 HTTP 接口、Python 标准库 | 应用内部模块和测试依赖 |
| `scripts` | 无依赖的开发、质量和验收编排 | 各应用公开命令 | 应用源码依赖、隐式生产密钥 |

应用之间通过 HTTP 或事件契约通信，不通过源码互相引用。契约由提供方持有并在提供方本地验证，消费者维护自己的边界模型；黑盒 E2E 负责发现跨应用不兼容。

## 逻辑架构

```text
Web -> API/BFF -> 原件域、抽取域、模板域、实例域、对比域、协作域
                  |                    |             |
             PostgreSQL + Redis      RabbitMQ        MinIO
                  |                    |             |
            加密敏感映射          Worker/AI Service -> Parser -> LLM -> Validator
```

API 负责鉴权、原件/模板/实例生命周期、敏感信息令牌化与回填、编辑锁、事务和任务投递；AI Service 只接收脱敏后的中间文档模型，负责解析辅助、抽取与语义差异分析，不能直接读取业务数据库或对象存储。搜索在 MVP 先使用 PostgreSQL 全文检索，规模增长后再接 Elasticsearch。

## 关键数据流

1. DOC/DOCX/PDF 直传 MinIO，API 保存不可变原件版本并发布 `source.version.created`；旧版 DOC 仅在隔离转换 Worker 中处理。
2. Worker 用 OOXML 或 PDF 版面解析器生成带节点 ID、页码、表格坐标的中间文档模型；同一模型生成原件只读预览和受控 HTML 初始模板。
3. 抽取前 API/Worker 执行敏感检测和稳定令牌化，映射加密保存；抽取器根据用户 Schema 调用模型，应用层再做 JSON Schema 校验、证据校验、默认值决策和受控回填。
4. 模板微调创建模板版本；基于模板创建实例，实例数据和文档内容分版本保存。
5. Web 使用 SSE 接收任务状态，使用 WebSocket 接收编辑锁、内容操作和实例保存事件；编辑者持有租约锁，其他用户实时只读同步。服务端将操作按节流策略落为实例快照，断线用户以快照恢复。
6. 对比服务区分“原件-模板人工校验”、“不可变版本的后端权威 Diff”和“编辑草稿的浏览器实时 Diff”。前者持久化并可审计；后者仅在 Web Worker 中计算，保存后由权威 Diff 取代。

## 非功能要求

服务无状态可横向扩展；任务至少一次投递、业务幂等；原始文件不可变；所有内部调用带 `request_id` 和 `trace_id`。默认 TLS、对象私有读、密钥放 Secret；日志脱敏，不记录完整文档和提示词中的敏感原文。编辑锁使用 Redis 租约加数据库版本号双重保护：连接中断后租约过期，保存时仍以乐观锁拒绝陈旧写入。

异步任务以数据库 `async_job` 作为可恢复发件箱，不依赖一次性的事务后回调。发布端使用短租约和 RabbitMQ publisher confirm；消费端按任务 ID、尝试编号和数据库状态幂等抢占，失败由数据库 `available_at` 控制指数退避并重新发布，耗尽次数后进入独立 DLQ。命令消息只传递受控 ID，不传文档内容、抽取值或敏感映射。Worker 处理租约过期后由定时恢复器重排，所有业务处理器仍必须满足至少一次执行下的幂等性。
