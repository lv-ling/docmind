# AI 流水线与评测

技术基线：T0.1  
适用产品：PRD v0.1  
状态：Draft

## 流程

```text
DOC/DOCX/PDF -> OOXML/PDF 解析 -> 带位置的中间模型 -> 敏感检测/令牌化
     -> Schema 约束抽取 -> JSON 校验 -> 令牌受控回填 -> 证据对齐 -> 默认值决策 -> 人工复核
```

确定性解析优先于 LLM：DOCX 使用 OOXML 解析，DOC 经隔离转换后进入同一模型，PDF 使用文本/版面解析并按需 OCR，保留段落、运行文本、表格、图片、页眉页脚、目录和位置。应用层采用 Microsoft Presidio + `libphonenumber` + `email-validator` + 自定义 Recognizer，在生成模型请求前替换身份证、国际手机号、国际邮箱和租户配置模式；首期规则覆盖中国、美国、日本、韩国、德国、法国、英国、澳大利亚和荷兰。租户正则只接受 RE2 安全方言，并限制表达式长度、词典规模、输入长度和扫描耗时，防止 ReDoS。LLM 只处理脱敏文本的字段语义与结构。模型输出在写日志、JSON 解析和令牌回填前再次扫描：任何明文 PII、未知令牌或被改造的令牌都拒绝并进入人工复核。HTML 模板由中间模型确定性生成，LLM 可提出修复建议但不能直接写入模板或原件。

## Agent 边界

采用有限状态工作流而非自由循环 Agent：`Parser`、`SensitiveTokenizer`、`Extractor`、`Validator`、`TokenRestorer`、`TemplateConverter`、`DiffAnalyzer`。LLM 通过 LangChain/LangGraph 的 provider adapter 调用，供应商、模型名、API Key、超时和预算来自服务端加密配置；业务工作流不绑定具体供应商，首选模型不可用时可切换 DeepSeek 或其他兼容供应商。每个节点有输入输出 Schema、超时、重试和预算；Supervisor 只选择预定义工作流，不执行任意工具调用。

## 输出契约

```json
{
  "data": {"amount": "100万元"},
  "fields": [{"path":"$.amount","value":"100万元","confidence":0.96,
    "evidence":[{"page":2,"text":"合同金额：100万元"}],"needs_review":false}],
  "model": {"provider":"...","model":"...","prompt_version":"..."}
}
```

若 JSON 校验失败，服务先尝试确定性修复，仍失败则进入 `review_required`，不能把自由文本当作成功 JSON。令牌回填后再进行字段类型和证据二次校验；模型返回的敏感明文、未知令牌或改造过的令牌均被拒绝并进入人工复核。字段无候选值时按“用户默认值，否则 `null`”处理；存在多个候选值时必须保留候选证据并进入人工复核。

## 评测与观测

建立脱敏黄金数据集，按文档类型、字段难度和覆盖国家分层；每个国家都包含正例、反例、国际区号、分隔符、全角/半角和 OCR 常见误差样本。指标包括字段准确率、默认值正确率、证据命中率、Schema 通过率、输入/输出/日志敏感泄漏率、令牌回填正确率、模板结构保留率、人工修改率、延迟和 Token 成本。每次模型/Prompt/解析器升级做离线回归，线上按工作区采样，支持按 `run_id` 重放。
