# 领域模型与数据库

技术基线：T0.1  
适用产品：PRD v0.1  
状态：Draft

## 核心实体

`app_user` 用户账号；`workspace` 工作区；`workspace_member` 成员与角色；`source_document` 原件逻辑对象；`source_version` 不可变 DOC/DOCX/PDF 版本；`source_preview` 原件只读预览；`parsed_content` 带位置的中间文档模型；`extraction_schema` 用户字段定义；`schema_template` 可复用 Schema 模板；`async_job` 通用异步任务；`extraction_run` 抽取运行；`extraction_field_result` 字段值、默认值来源和复核状态；`extraction_candidate` 多候选值；`extraction_evidence` 字段或候选值证据；`sensitive_rule_template` 可复用敏感规则模板；`sensitive_token` 加密令牌映射；`llm_provider_config` 加密的供应商/模型配置；`template` 逻辑模板；`template_version` 受控 HTML 模板版本；`document_instance` 模板实例；`instance_version` 实例内容和数据快照；`edit_lock` 编辑租约；`comment_thread/comment` 版本锚定批注；`proofreading_run/proofreading_suggestion` 纠错任务及人工处置；`diff_run/diff_change` 不可变版本的权威对比结果；`audit_event` 审计事件。

## 关系与约束

- 所有业务表带 `workspace_id`、`created_at`、`updated_at`；软删除使用 `deleted_at`。
- `app_user.email` 规范化为小写并唯一，密码仅保存自描述的单向哈希；JWT 不保存邮箱、敏感数据或工作区角色。`workspace_member` 以 `(workspace_id, user_id)` 唯一，角色为 `owner/admin/editor/reviewer/viewer`，权限在对象访问时依据当前有效成员关系判断。
- 工作区创建以 `(created_by, creation_idempotency_key)` 唯一并保存请求哈希：相同键和相同请求返回已有对象，相同键和不同请求返回 `IDEMPOTENCY_CONFLICT`。
- `audit_event` 记录工作区、操作者、动作、目标、结果、请求 ID、时间与不含敏感明文的元数据；数据库触发器禁止更新和删除，确保追加式审计。
- `source_version` 通过 `(source_document_id, version_number)` 唯一；staging 与 immutable 对象键分别唯一，SHA-256 按工作区索引用于完整性与重复检测，但不禁止同一文件出现在不同业务文档中。仅允许 DOC/DOCX/PDF 且 `size_bytes <= 10MiB`。完成上传时按 staging ETag 条件复制到新的 immutable key，过期的预签名 PUT 因此不能覆盖已确认版本；原件也永不被模板编辑覆盖。
- `extraction_schema_field` 以 `(schema_version_id, key/json_path/position)` 分别唯一，保存类型、字面量默认值、约束、敏感级别、展示配置和非执行元数据；`schema_template` 指向一个不可变且已发布过的 Schema 版本，旧模板不会随 Schema 后续版本漂移。
- `async_job` 通过 `(aggregate_type, aggregate_id)` 唯一绑定一个业务运行，记录尝试次数、最大次数、下次可运行时间和终态；`extraction_run` 以 `(source_version_id, created_by, creation_idempotency_key)` 保证创建幂等，并固定引用原件、Schema 和可选敏感规则版本。
- `extraction_field_result`、`extraction_candidate` 和 `extraction_evidence` 分表保存最终值、多候选值及证据位置。结果、字段值、人工修改值、候选值和证据原文只能写入加密信封 JSONB 列；单独的 `masked_preview` 不含完整明文，用于无敏感查看权限时展示。候选证据使用复合外键约束在同一字段内，证据偏移必须成对存在且 `end_offset >= start_offset`。
- `sensitive_rule_template_version` 和其规则不可变；自定义正则以 RE2 编译，词典限制项数与总字符数，校验器只能引用 allowlist 名称，不能动态加载用户代码。`sensitive_token` 仅保存加密后的原始值、类型、令牌和任务作用域；令牌不可跨工作区、任务或版本复用。
- `llm_provider_config` 的 API Key 使用 Secret/KMS 加密，前端只能看到供应商和模型名，不能读取密钥明文。
- `template_version` 关联唯一的来源 `source_version_id` 与 `parsed_content_id`；`document_instance` 关联固定 `template_version_id`，不得因模板后续编辑而改变。
- `instance_version` 带递增 `revision`；保存时需携带 revision。`edit_lock` 以 `(instance_id)` 唯一，保存锁持有人、租约过期时间和最后心跳。
- `comment_thread` 关联创建时的 `instance_version`，并保存节点、范围、原文引号及前后上下文；重挂载失败必须显式标记，不能静默迁移。`proofreading_suggestion` 也使用相同锚点；接受时必须在持锁且版本未冲突的实例上创建新版本，并记录该版本 ID，忽略时保留处置人、时间和原因。
- `diff_run` 只引用不可变的 `source_version/template_version/instance_version`；上传文件先建立临时 `source_version`，因此可与任意系统版本比较。浏览器草稿 Diff 不入库，也不写入审计结果。

## 状态机

```text
source_version: uploading -> uploaded -> processing -> ready | failed
extraction_run: queued -> running -> review_required -> approved
                         |          |                 \-> failed -> retrying
template_version: generated -> checking -> published -> superseded
document_instance: draft -> editing -> saved -> submitted -> archived
diff_run: queued -> parsing -> comparing -> completed | failed
```

状态转换由服务端校验；客户端不能直接写状态。任务重试使用指数退避和最大次数，人工审批和实例提交是显式命令。编辑锁不等同于实例状态：锁释放后实例仍可能处于 `editing` 或 `saved`。

## 数据保留

原始文件、版本和审计记录默认保留 365 天，工作区可配置；删除采用回收站 + 延迟清理。模型输入输出按敏感等级脱敏后保留最小必要周期，禁止使用租户数据训练，除非有明确授权。
